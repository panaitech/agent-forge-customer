# 行业案例（防水材料制造 / B2B 直销参照）

> 用途：为雨中情「合同 AI + 企业知识库 + 多智能体协作」方案设计提供外部机制参照。
> **边界声明：以下均为公开信息中的第三方案例，与 Agent Forge 无客户关系，也不是 Agent Forge 的自有案例或已复现成果。** 厂商公布的效率数字未经独立审计，对外引用前须人工复核原文。
> 检索时间：2026-10-22。本次**未检索到防水材料行业可公开核实的多智能体协作案例**，东方雨虹等同行亦未见可核材料，故以「相近行业 + 跨行业机制」为主。

**证据级别口径（按本任务）**：A=一手官方案例/年报/监管披露；B=厂商官方客户故事或权威媒体一手报道；C=行业媒体/研究机构二手；D=厂商营销材料/无独立核实；E=传闻/不可核。
**行业标签**：同业（防水/建材）｜相近（制造、家居建材、工程链条）｜跨行业（仅机制参考）。

## 一、合同智能

### 案例 1｜某制造型科技企业 × 深信服 FastGPT：法务自建合同审查 Agent

**场景/行业标签：合同审查辅助｜相近（制造型科技企业，年签约数千份）**

- **做法**：法务人员零代码选用 Agent 模板，搭建「上传—风险审查—出具意见」全流程；解析跨页表格、手写批注；法务每次「确认风险/忽略误报」回流校准。
- **公开结果**：单份审查由 5 小时降至 5 分钟，原文称「效率提升近 60 倍」；法务工作量减少 60%；风险漏检率「大幅降低」（未给数字）。
- **来源**：深信服官网《不靠 AI 专家，这家企业搭建的法务 Agent……》，https://www.sangfor.com.cn/news/69e531292f8e41beba2de39a03978b8d ，2026-05-12。
- **证据级别：B**（厂商官方客户故事；客户匿名，基线不可独立核验）。
- **对齐点**：合同审查只做辅助、法务终审保留；用真实确认/误报做反馈闭环；知识私有化，贴合「人在环 + 可积累」。
- **不对齐点**：单 Agent 串行工具链，不是多角色协作；未接 CRM/审批/用印，不构成端到端业务自动化；效果为厂商单方口径。

### 案例 2｜宁夏宝丰能源 × e签宝：多系统合同识别、审查与用印联动

**场景/行业标签：合同识别、审查与用印联动｜相近（能源化工流程制造，重资产 B2B）**

- **做法**：合同来自合同管理、集采、OA、HR、园区、LIMS、财务共享、运销、条码等 12 类系统；识别归集后按规则库逐条审查，结论定位到条款；**审查通过才发起用印，高风险挂起人工确认**；用印未完成则条码系统锁定、无法领料。
- **公开结果**：未披露量化收益；已实现盖章文件可存档、可下载、可监控，审查记录与用印记录同源可追。
- **来源**：e签宝技术博客，https://www.esign.cn/blog/multi-system-ai-contract-management-202610 ，2026-10-10。
- **证据级别：D**（厂商技术文章，客户具名但无第三方核实，效果部分为方案描述）。
- **对齐点**：把「AI 意见」变成流程闸门而非建议；审批、用印、业务动作串成一条链；全程留痕，最接近雨中情「合同→审批→盖章→发货」。
- **不对齐点**：主体是电子签章与规则引擎，AI 审查占比不明；非多智能体；未证明风险识别准确率。

### 案例 3｜视源股份 × 实在智能：合同/单据 IDP 审阅

**场景/行业标签：合同/单据 IDP 审阅｜相近（电子制造，B2B 多品类）**

- **做法**：以 IDP 文档审阅 + RPA 处理合同与单据，规则化抽取、比对、复核。
- **公开结果**：客户评价页称「合同审核效率提升 10 倍」「数据处理正确性 100%」「节约人力成本 70%」。
- **来源**：实在智能客户案例页，https://www.ai-indeed.com/customerCase/0.html ，页面未标注日期（访问 2026-10-22）。
- **证据级别：D**（厂商客户评价摘录，无评测口径与样本）。
- **对齐点**：文档密集型环节先做抽取与比对，人工只看异常，适合合同创建/初审。
- **不对齐点**：单点工具，非协作式 Agent；「100% 正确」属营销表述，不可作为验收标准。

## 二、企业知识库与销售赋能

### 案例 4｜某大型软件企业 × 天润融通：知识库从「弃用」到「好用」

**场景/行业标签：对外知识库重构｜跨行业（软件，多产品线、多渠道）**

- **做法**：1.5 万+ 条知识按角色分权（内部员工/渠道商/终端客户/访客），编辑、审核、发布、查看四类权限分离；语义检索；用三套扩写模型把语料扩到 15 万条；配套知识梳理与运营方法。
- **公开结果**：语料 1.5 万→15 万条；自助查询替代部分人工支持；原文未给成本下降比例。
- **来源**：新浪财经转载 CTI 论坛，https://finance.sina.com.cn/roll/2025-02-11/doc-inekanhh3428893.shtml ，2025-02-11。
- **证据级别：C**（行业媒体二手转载，原始来源为厂商案例）。
- **对齐点**：权限分级 + 审核发布 + 语料扩写，正是雨中情「团队—知识库—文件夹」三级权限与知识质检的参照。
- **不对齐点**：面向对外客服，不是销售打法萃取；无提问分析、推送与陪练；不是多智能体。

### 案例 5｜EC × 腾讯乐享：「销售充电站」AI 问答

**场景/行业标签：销售知识问答｜跨行业（SaaS 销售组织，机制最接近雨中情销售团队）**

- **做法**：把产品、方案、话术沉淀进「销售充电站」，销售在企微侧提问，AI 基于知识库回答并附参考链接。
- **公开结果**：销售自助解决比例提升至 30%；平均 30 秒取答案，对比人工 5–10 分钟，原文称效率提升超 10 倍。
- **来源**：搜狐转载行业媒体，https://m.sohu.com/a/867289100_99984157 ，2025-03-05。
- **证据级别：C**（行业媒体二手，数字来自厂商案例）。
- **对齐点**：知识库直接嵌进销售日常工具；答案带出处可溯源；先用高频问题打透。
- **不对齐点**：仍是「问答机器人」，没有拜访结构化、陪练与商机回填；未解决知识贡献激励。

### 案例 6｜武田（Takeda）× Salesforce Agentforce：受监管知识问答

**场景/行业标签：受监管知识问答｜跨行业（医药，强监管、强溯源）**

- **做法**：以 Agentforce 汇总 3,100+ 份医学文件，处理 25,000 次医护人员咨询，回答附引用。
- **公开结果**：厂商称实现「citation-backed responses」，未给准确率或工时降幅。
- **来源**：Salesforce 客户故事，https://www.salesforce.com/customer-stories/takeda ，页面未标注日期（访问 2026-10-22）。
- **证据级别：B**（厂商官方客户故事，客户具名）。
- **对齐点**：强监管场景下「先引用、再回答」，与合同/技术条款回答的溯源要求同构。
- **不对齐点**：单 Agent 问答，不涉及销售流程与审批；行业差异大，不能外推效果。

## 三、CRM/ERP 业务流程自动化

### 案例 7｜三花智控 × 实在智能：业务人员自建自动化

**场景/行业标签：跨系统流程自动化｜相近（汽车零部件/制冷部件制造，多基地）**

- **做法**：以 Agent/RPA 让业务人员自行搭建跨系统取数、报表、单据流程；配套数字化人才认证。
- **公开结果**：769 名员工通过认证，落地 340+ 场景，累计节省超 20 万工时，平均每天一个新流程上线。
- **来源**：实在智能客户案例页，https://www.ai-indeed.com/customerCase/0.html ，页面未标注日期（访问 2026-10-22）。
- **证据级别：D**（厂商客户故事，工时口径未披露）。
- **对齐点**：把「谁能改流程」从 IT 下放到业务，适合雨中情销管/商务自建审批辅助；规模推广靠认证与场景库。
- **不对齐点**：RPA 流程自动化≠多智能体协作；节省工时不能直接换算为减员或利润。

### 案例 8｜志邦家居 × 实在智能：管理流程自动化

**场景/行业标签：订单/成本/库存流程自动化｜相近（定制家居/建材渠道制造）**

- **做法**：「痛点先行」，用 Agent + AI 表格改造订单、成本、库存等管理流程。
- **公开结果**：厂商称形成「可落地、可复制的协同运营体系」，未给量化数字。
- **来源**：实在智能客户案例，https://www.ai-indeed.com/aboutNews/19533.html ，页面未标注日期（访问 2026-10-22）。
- **证据级别：D**（厂商营销材料）。
- **对齐点**：家居建材行业的渠道/订单/成本场景，与防水材料经销与工程单有相似性。
- **不对齐点**：无量化结果、无权限与审计细节；不可作为收益依据。

## 四、多智能体协作落地

### 案例 9｜SaaStr × Salesforce：20+ Agent 统一编排

**场景/行业标签：销售与外联多 Agent｜跨行业（会展/社区型 B2B 营销）**

- **做法**：3 人团队把销售开发、服务、语音礼宾等 20+ 个 Agent 统一在一个平台，共享客户数据与编排层。
- **公开结果**：厂商称促成 2.7 百万美元成交、外联打开率 72%。
- **来源**：Salesforce 客户故事，https://www.salesforce.com/customer-stories/saastr-ai ，页面未标注日期（访问 2026-10-22）。
- **证据级别：B**（厂商官方客户故事，客户具名；数字未经独立审计）。
- **对齐点**：多 Agent 按职能分工、共享上下文与统一治理，是「多智能体协作」少数可核的商用样本。
- **不对齐点**：营销外联场景，非合同/审批；强绑定单一厂商生态；「20+ Agent」不等于 Agent 间真协作，可能是并列工具集。

### 案例 10｜Anthropic Research：orchestrator-worker + 引用校验

**场景/行业标签：研究型多 Agent｜跨行业（工程机制参考）**

- **做法**：主 Agent 规划并派生并行子 Agent；子 Agent 各自检索、评估、回传；最后由 CitationAgent 为每条结论定位出处；全链路记录交互结构做可观测，采用灰度发布避免打断运行中 Agent。
- **公开结果**：内部评测中多 Agent 比单 Agent 高 90.2%；token 消耗约为聊天的 15 倍；同步执行是瓶颈。
- **来源**：Anthropic Engineering，https://www.anthropic.com/engineering/multi-agent-research-system ，2025-06-13。
- **证据级别：C**（单方工程披露，非客户业务案例，无独立复核）。
- **对齐点**：规划—执行—校验—引用四段式；把「证据」与「结论」分离；可观测看协作结构而非对话内容。
- **不对齐点**：研究任务可并行，合同审查是强顺序、强责任链，盲目多 Agent 会放大时延与成本；无人工审批与业务写回。

## 证据充分度小结

- **数量与覆盖**：10 条，覆盖合同智能 3、知识库/销售赋能 3、流程自动化 2、多智能体 2；中国大陆企业 6 条。
- **级别分布**：A 0、B 3、C 3、D 4。**无 A 级**——没有上市公司年报或监管披露直接描述上述 AI 项目；B 级也只有厂商客户故事。
- **可迁移机制（相对可靠）**：①AI 意见只做「评审卡片」，高风险必须人工确认；②审查结论影响用印/发货等下游权限；③知识按角色分权、审核后发布、回答带出处；④业务人员自建流程 + 认证推广；⑤多 Agent 需主控规划、引用校验、交互级可观测。
- **证据薄弱处**：所有效率倍数均来自厂商；匿名客户无法核基线；「准确率/漏检率」普遍没有评测集口径；多智能体案例多为营销/研究场景，缺中国企业业务闭环。

## 不可直接外推的结论

1. **5 小时→5 分钟不可移植**：依赖合同模板化、类型集中、历史语料充足；雨中情工程合同含月结、结算款、宽限期等非标条款，需重新测基线。
2. **「效率提升 N 倍」不能写进方案效益**：未区分等待、返工与人工复核时间，且无对照组。
3. **RPA 节省工时 ≠ 降本**：20 万工时是理论节省，不等于编制优化或利润。
4. **单 Agent ≠ 多智能体**：上述中国案例多为单点 Agent/RPA；把「流水线编排」说成「多角色协作」属于概念放大。
5. **多智能体不是默认更优**：Anthropic 自述 token 约为聊天 15 倍，且强顺序任务不适合；合同审查应优先「单 Agent + 规则/工具 + 人工闸门」。
6. **知识库上线 ≠ 知识可用**：权限与审核只解决「敢用」，回答质量仍取决于知识萃取、版本降级与运营激励；天润案例的 10 倍语料扩张也可能放大噪声。
7. **同业空白**：本次未检索到防水材料行业公开可比案例，任何「同行已这样做」的表述都缺乏公开证据。
