# 合同录入作业标准

演示数据全部虚构，文首标明「演示虚构，非雨中情合同」。不接销售易，不盖章，不建单，不定责。

## 目标

把报价单或扫描件推进到可人工确认的填单草稿。字段带来源；物料只给 Top-3；缺的不猜。

## 交接

每一项至少包含：字段、值、置信度、出处（页 / 段 / 单元格）、校验结果。缺失进入追问清单，不填猜测值。

| 置信度 | 处理 |
| --- | --- |
| ≥ 0.90 | 可建议采纳；首期仍逐项人工确认 |
| 0.70–0.90 | 标待核，不自动填入正式字段 |
| < 0.70、冲突或无出处 | 挂起，不写回 |

## 步骤

1. **收件识别**  
   `list_cases` / `get_case`。扫描件调用 `ocr_attachment`。服务不可用时工具回退预置文本，交付物必须写 `source=fixture`。机读报价单直接读文本。OCR 文本仍须对照原件，不得当成已确认字段。

2. **要素提取**  
   抽出客户、项目、金额、付款比例、账期、收货、质保。每项带出处和置信度。无出处不成立。金额、比例只摘录原文，不心算、不改数。

3. **清单匹配**  
   调用 `search_material` 与 `match_lines`。产出已匹配、未匹配、Top-3。别名不能唯一命中时，不得把 Top-3 第一条写成已匹配，不得自动落内部编码。别名表是假设口径。

4. **缺件追问与草稿**  
   汇总缺口，起草 `填单草稿.md`。正式写回只走 `upsert_contract_draft`，并等待人工批准。人未批准则草稿不落账。

## 红线

- 把猜测写进正式字段即不合格。
- 禁止审批通过、用印、建单。
- 不输出「可签 / 不可签」，不建议签署。
