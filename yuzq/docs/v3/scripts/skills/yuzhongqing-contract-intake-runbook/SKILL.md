# 合同录入作业标准

演示数据全部虚构。文首可以留一句「演示数据，不是雨中情合同」。不接销售易，不盖章，不建单，不定责。

读者是销售。写进 Markdown 的正文用业务语言。不要写工具名、参数名、置信度、语料文件名。

## 你只做自己那一步

角色说明会点名你要写入的那一个文件。下面各步是整条链的分工，不是你的任务清单。只写被点名的那一个文件，禁止创建其他岗位的文件。

## 目标

把报价单或扫描件做成一张预填单。字段带来源。物料能对上就写内部名称，对不上只给候选。缺的问销售，不猜。销售逐项确认后，这张单才算数。

## 预填单怎么写

每一行四列：字段、预填值、出处、待确认。

- 出处写报价哪一行，或合同哪一句。没有出处就不填值。
- 待确认写「请销售确认」或「请销售补充」。
- 物料对上了写「已对应内部名称」，并写出名称。对不上写「只给候选，不自动编码」，列出至多三个候选。
- 扫描件这次没识别成，写「这次没识别成，对照的是预先准备的文字」。不要写 `source=fixture`。

## 步骤

1. **收件识别**  
   打开指定案例。扫描件做识别，机读报价单直接读文本。写入 `收件识别.md`：附件齐不齐、文字从哪来。识别结果不是已确认字段。

2. **要素提取**  
   抽出客户、项目、金额、付款比例、账期、收货、质保。每项写预填值和出处。无出处不写正式值。金额、比例只摘原文，不心算、不改数。写入 `要素提取.md`。

3. **清单匹配**  
   报价行对物料别名。产出已对应、未对应、候选。别名不能唯一命中时，不得把第一个候选写成已对应，不得自动写内部编码。写入 `清单匹配.md`。

4. **缺件追问与预填单**  
   汇总缺口，起草 `填单草稿.md`，按上面的四列。正式写入须等销售批准。人未批准则这张单不算数。

## 红线

- 把猜测写进正式字段即不合格。
- 禁止审批通过、用印、建单。
- 不输出「可签 / 不可签」，不建议签署。
- 正文禁止出现工具名、参数名、置信度。
