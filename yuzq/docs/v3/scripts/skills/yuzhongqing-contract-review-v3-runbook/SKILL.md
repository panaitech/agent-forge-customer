# 合同评审作业标准（v3）

演示数据全部虚构。基础初审之后，技术标注、商务标注、法务提示同时进行，再收成一张评审卡。不定责，不用印，不建单。

读者是销售和评审人。写进 Markdown 的正文用业务语言。不要出现工具名、参数名、语料文件名、置信度、MCP 名。条目编号可以写在依据后面，前面先写业务名称，例如「双组分聚氨酯防水涂料（TEC-PU-2）」。

## 你只做自己那一步

角色说明会点名你要写入的那一个文件。下面各步是整条链的分工，不是你的任务清单。只写被点名的那一个文件，禁止创建其他岗位的文件。技术、商务、法务互不引用对方的文件，付款结论只引用基础初审。

## 结论只用这三种

- **通过 / 不通过**：单据已经比对完。付款、金额、地址用白话写结果，例如「四个节点加总 105，比 100 多 5」。
- **待补**：依据要求合同写，正文没写。施工条件、质保年限、赔偿、违约、宽限期用这个，不叫无法判断。
- **无法判断**：只用在合同里已经写了具体编号或数字、依据对不上、不能编的时候。没有条目的题不要写这一行。

不上卡：包装储运、检测复验、技术方案是否合格、授权是否超限、地址的法律定性。不要写「未覆盖项清单」。

## 步骤

1. **基础初审**  
   对照报价、合同、签收。产品、价格、交期、付款比例、行金额、地址是否一致，只引用复算结果，不得自行加总后改结论。写入 `基础初审.md`，表格列为：事项、结论、说明。说明里写两侧原文，不写参数名。

2. **技术条款标注**  
   只拿合同里出现的品名和项目名各查一次技术依据。003 就是「双组分聚氨酯」「非固化」「屋面补强」。查完即停。不要用验收、检测、包装、储运、方案是否合格、质保期去扩搜。质保归法务。  
   只写返回了条目编号的行。没有编号就不要写。不判定技术方案是否合格。写入 `技术标注.md`。

3. **商务风险标注**  
   用商务依据看付款、赔偿、违约、宽限期。修改建议必须带回条目编号。付款加总是否为 100 仍只引用基础初审已经写明的复算结果，不另算。没有条目编号的行不写。不判断授权是否超限。写入 `商务标注.md`。

4. **法务风险提示**  
   用法务依据看质保年限、验收标准、有没有标准号、付款比例。命中才写。合同没写标准号时，这一行结论写待补，说明里可以带一句「具体标准号无法判断」。不定责，不出现「可签 / 不可签」。写入 `法务提示.md`。

5. **评审卡片**  
   只汇编上游已经写出的行，不新开栏目。写回须人工批准。

6. **执行与变更提醒**  
   发货排产、补充协议、退换货各写一行。标明只是提醒。不写回。

## 红线

- 单据核对的不通过必须来自复算，不来自口述加总。
- 技术、商务、法务没有条目编号的行不成立。
- 禁止把模型补写的国标、判例或历史意见当成依据。
- 禁止输出签署建议，禁止定责，禁止用印和建单。
- 正文禁止出现工具名、参数名、语料文件名、置信度。
