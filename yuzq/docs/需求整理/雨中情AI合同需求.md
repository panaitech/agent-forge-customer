# 合同业务现状与AI建设定位

## 业务流程现状

- 业务流程：合同创建登记 → 初审 → 技术评审 → 商务评审 → 法务评审 → 客户盖章 → 归档；包含提前发货（客户口头确认后先入场发货、后补正式合同）、合同变更、补充协议、退换货等场景。

- 报价环节：报价是合同的充分非必要条件；权限内（如无折扣或9折以内）可直接创建合同，特价超授权走报价单审批，权限逻辑由系统自动判定。

- 审核分工：权限内合同由各区域商务审核，大系统平台以上合同由集团商务审核；法务关注法务风险，财务合作数据由系统抓取。

- 系统规则：后台按账期设置对后续发货做限制（如账期6个月），防止过度承诺。

- 开发基础：合同模块基于销售易平台Java二次开发，表单为结构化字段。

# 需求明细（按合同生命周期）

## 合同创建登记

- 字段提取：支持PDF、图片OCR识别（实测识别率90%以上，评测约98%），Word版本可直接匹配，自动提取合同关键字段。

- 自动填表单：高置信度字段自动填写，低置信度字段标黄由员工确认。

- 产品映射：报价单明细自动带入合同详情（需开发适配）；产品清单按统一物料名称、编码规则匹配。

- 核心要义提取：提取合同核心条款，形成摘要，方便后续审批决策与风险反馈。

## 初审

- AI校验产品、价格、交期等基础信息。

- 预期效果：区域专员审核量从一天50单提升到一天200单。

## 技术评审

- 整理进对应知识库，审查时检索并引用条目原文后，AI对技术条款做初步标注，辅助技术评审人员。

## 商务评审

- AI识别并标注商务风险条款：付款条件、赔偿条款、违约条款、宽限期等。

- 给出修改建议：识别哪些类型条款不宜接受及修改方式，历史评审意见、不宜接受的条款类型和修改口径作为可引用条目；建议必须带回条目，不能只给模型发挥。

- 评审卡片：合同进入系统后，AI生成评审意见卡片（如5层递进式审查），人工确认后流转。

## 法务评审

- 典型法律条文、国家标准等整理进对应知识库，审查时检索并引用条目原文，AI辅助分类风险点、提示不宜接受的条款及修改方式。

- 无出处不成立；知识库未覆盖或条文对不上时，必须写明「无法判断」，不生成修改意见。

- 人工确认兜底：AI输出意见后仍须法务人工审核。

## 执行与变更

- 合同执行、发货排产、变更补充协议、退换货等环节的AI辅助提醒（方案细化中）。

# 预期效果

# 实施原则与边界

- AI不做最终决策、不直接放行合同，人工审核必须保留。

- 灰度发布：先小范围「人工 \+ AI」双线并行验证，再逐步扩大范围。

- 数据安全与保密：涉及合同材料，双方签署保密协议；训练与处理可在贵司指定环境内进行，材料不离开贵司管控范围。
