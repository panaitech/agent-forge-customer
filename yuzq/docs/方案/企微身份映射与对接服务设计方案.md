# 雨中情 · 企业微信身份映射与对接服务设计方案

| 项 | 内容 |
| --- | --- |
| 文档性质 | 对外技术设计说明 |
| 适用对象 | 客户信息技术 / 平台 / 安全相关评审 |
| 版本日期 | 2026-10-31 |
| 关联能力 | 企业微信合同助手入口；Agent Forge 运行时与控制台 |
| 范围边界 | 本文覆盖身份映射、鉴权授权、企微对接服务（WeCom Bridge）。不覆盖合同抽取算法、会审规则引擎、销售易字段级接口明细（另案勘察） |

---

## 1. 目标与原则

### 1.1 设计目标

1. 业务人员在企业微信自建应用会话中提交合同材料并接收任务进度，无需另行注册 Agent Forge 业务账号。  
2. 企业微信成员身份与 Agent Forge 任务归属一一对应，保证会话隔离、审批归属与审计可追溯。  
3. 企业微信回调协议与 Agent Forge 运行时解耦：对接逻辑独立部署，运行时不承载企微协议实现。  
4. 身份主数据以企业微信通讯录为准；映射关系由确定性规则生成并由对接服务维护。

### 1.2 设计原则

| 原则 | 说明 |
| --- | --- |
| 身份源单一 | 成员生命周期以企业微信通讯录及应用可见范围为权威来源 |
| 规则确定性 | `userid → owner_id` 由固定生成规则计算，禁止按人手工指定业务侧用户名作为主路径 |
| 凭证隔离 | 业务终端用户不持有 Agent Forge API 凭证；API 调用仅由对接服务使用机器账号完成 |
| 最小暴露 | 企业微信侧仅推送业务可理解的受理、阶段与待办信息；推理轨迹与内部工具细节留在控制台/审计 |
| 职责分层 | 鉴权决定「请求是否允许进入」；映射决定「任务归属哪一成员」；RBAC 决定「该成员可执行哪些操作」 |

## 2. 总体架构

### 2.1 逻辑拓扑

```text
┌─────────────────┐     回调 / 出站 API      ┌──────────────────────┐     HTTPS + Basic Auth     ┌─────────────────┐
│  企业微信平台    │ ◄──────────────────────► │  WeCom Bridge         │ ◄───────────────────────► │  Agent Forge    │
│  自建应用        │                          │  （企微对接服务）       │   机器账号               │  Runtime/API    │
│  通讯录          │                          │  · 验签解密            │   显式 tenant/owner      │  Console        │
└─────────────────┘                          │  · 身份链接维护        │                          └─────────────────┘
                                             │  · 附件拉取与落库      │
                                             │  · 任务创建与进度订阅  │
                                             │  · 出站消息 / ticket   │
                                             └──────────────────────┘
```

### 2.2 组件职责

| 组件 | 职责 |
| --- | --- |
| 企业微信自建应用 | 工作台入口、成员可见范围、消息与文件入站、应用消息出站 |
| WeCom Bridge | 回调接入、通讯录同步、身份链接表维护、媒体下载、调用 Agent Forge、进度映射与回推、确认深链签发 |
| Agent Forge | 多租户会话与协作运行、人工确认（HITL）、产物存储、审计与 RBAC |
| 销售易（后期） | 确认后草稿字段写回；身份延伸至 CRM 用户主键（独立勘察） |

### 2.3 部署约束

- Bridge 以独立进程（或独立容器）部署，具备独立配置、密钥与日志。  
- Agent Forge 不实现企业微信加解密与回调协议。  
- 生产环境 Bridge 与 Agent Forge 之间建议内网或受控专线；公网暴露面限于企微回调入口（HTTPS）。  
- 演示环境与客户生产环境使用不同 `corp_id` 与不同 Agent Forge 租户，数据隔离。

## 3. 标识体系

### 3.1 两侧主键

| 域 | 标识 | 语义 |
| --- | --- | --- |
| 企业微信 | `corp_id` | 企业唯一标识 |
| 企业微信 | `userid` | 企业内成员唯一标识；回调与消息寻址主键 |
| Agent Forge | `tenant_id` | 租户隔离键 |
| Agent Forge | `owner_id` | 任务/会话归属者键 |
| Agent Forge | `role` | RBAC 角色（如 `operator` / `approver` / `admin` / `readonly`） |

### 3.2 企业级绑定

每个接入的企业微信企业配置一条租户绑定：

| 配置项 | 约束 |
| --- | --- |
| `corp_id` ↔ `af_tenant_id` | 一对一；变更须走变更流程 |
| 默认 `af_role` | 新成员建档时的缺省角色（建议 `operator`） |
| 应用可见范围 | 在企业微信管理端配置；决定可使用合同助手的成员集合 |

### 3.3 成员级归属生成规则

对落入应用可见范围且状态有效的成员：

```text
af_owner_id = "wecom:" + corp_id + ":" + userid
```

规则特性：

- 全局唯一（在给定 `corp_id` 命名空间内与 `userid` 一一对应）。  
- 可重算、可校验，同步任务与消息兜底使用同一公式。  
- 禁止多成员共用同一业务 `owner_id`。

## 4. 身份链接模型

### 4.1 表：`wecom_identity_link`

同步结果的物化存储，供消息处理路径快速判定。

| 字段 | 类型意图 | 来源 / 规则 |
| --- | --- | --- |
| `corp_id` | 字符串 | 企业微信 |
| `userid` | 字符串 | 企业微信 |
| `af_tenant_id` | 字符串 | 企业级绑定配置 |
| `af_owner_id` | 字符串 | 第 3.3 节生成规则 |
| `af_role` | 字符串 | 默认角色；可被例外表覆盖 |
| `status` | 枚举 | `active` / `disabled` |
| `display_name` | 字符串，可选 | 通讯录只读缓存 |
| `dept_ids` | 列表，可选 | 通讯录只读缓存 |
| `synced_at` | 时间戳 | 最近一次同步或兜底写入时间 |
| 主键 | `(corp_id, userid)` | |

### 4.2 例外表（少量运维配置）

| 用途 | 行为 |
| --- | --- |
| 角色覆盖 | 指定 `userid` 使用非默认 `af_role`（如审批人） |
| 强制停用 | 指定 `userid` 的 `status=disabled`，即使仍在通讯录可见范围 |

例外表不承担「逐人指定自定义 `owner_id`」职责。

## 5. 通讯录同步

### 5.1 同步范围

- 数据源：企业微信通讯录 API，和/或成员变更回调事件。  
- 过滤条件：成员在职，且属于自建应用可见范围（或可见部门并集）。  
- 动作：对符合条件的成员 upsert 链接行；对离职、移出可见范围或强制停用的成员置 `disabled`（或删除链接，与实现选型一致，须保证后续消息拒绝）。

### 5.2 触发方式

| 方式 | 说明 |
| --- | --- |
| 首次全量 | 上线时执行一次全量拉取与建档 |
| 定时增量 / 全量 | 按运维策略周期性对齐 |
| 事件驱动 | 接收成员新增、更新、离职等事件后即时 upsert |

### 5.3 消息路径兜底

当合法回调到达且链接表尚无对应行时，Bridge 按第 3.3 节规则即时 upsert 一行后再继续建任务。兜底与同步使用同一生成规则与同一租户绑定。

### 5.4 通讯录权限未就绪时的过渡方案

在通讯录 API / 变更回调尚未开通的阶段：

1. 自企业微信管理端导出应用可见范围成员清单（含 `userid`）。  
2. 由实施脚本按第 3.3 节规则批量 upsert `wecom_identity_link`。  
3. 保留消息路径兜底。  
4. 通讯录同步上线后，过渡导入退出主路径。

## 6. 鉴权与授权

本节将「能否进入系统」与「任务归属何人」分开描述。

### 6.1 控制面分层

| 层级 | 控制对象 | 机制 |
| --- | --- | --- |
| L-A 企业微信入站 | 回调请求真伪 | Token / EncodingAESKey 验签与解密；拒绝伪造回调 |
| L-B 成员准入 | 谁可使用合同助手 | 应用可见范围 + `wecom_identity_link.status` |
| L-C 平台 API | 谁可调用 Agent Forge | Bridge 机器账号 Basic Auth（或组织服务账号）；密码仅存于服务端配置 |
| L-D 任务归属 | 会话与 HITL 归属 | 请求显式携带映射得到的 `tenant_id` / `owner_id`（及 role） |
| L-E 确认深链 | 浏览器打开控制台任务 | Bridge 签发短时签名 ticket；绑定 tenant、owner、session/run、过期时间 |
| L-F 操作权限 | 审批、只读等 | Agent Forge RBAC（`af_role`） |

### 6.2 企业微信回调验签与解密原理

本节对应控制面 **L-A**，遵循企业微信「接收消息与事件」回调规范。算法细节以企业微信官方文档及官方加解密库为准；实现上优先接入官方库，避免自行实现 AES/签名细节。

#### 6.2.1 回调侧共享配置

在企业微信管理后台为自建应用配置接收消息时，与 Bridge 共同持有：

| 配置项 | 用途 |
| --- | --- |
| 回调 URL | Bridge 对外 HTTPS 入站地址 |
| Token | 双方约定的校验口令，参与签名计算 |
| EncodingAESKey | 43 位密钥材料，派生 AES 密钥，用于消息体加解密 |

上述参数仅存于企业微信后台与 Bridge 服务端配置（或密钥管理系统），不向业务终端用户分发。应用 `Secret` 用于 Bridge **主动调用**企业微信 API（通讯录、素材下载、应用发消息），与回调验签所用 Token / EncodingAESKey 职责不同。

#### 6.2.2 验签（消息认证）

企业微信每次向回调 URL 推送时，请求中携带 `msg_signature`、`timestamp`、`nonce`，以及加密后的消息体字段（如 `Encrypt`）。

Bridge 校验步骤：

1. 取本地配置的 `Token`，与请求中的 `timestamp`、`nonce`、加密串 `Encrypt` 组成四个字符串。  
2. 字典序排序后拼接，对拼接结果做 SHA1，得到计算签名。  
3. 与请求中的 `msg_signature` 比对：一致则接受；不一致则拒绝并丢弃，不进入业务处理。

效果：未持有正确 Token 的调用方无法伪造可通过校验的回调；篡改加密串会导致签名不匹配。

#### 6.2.3 URL 初次校验（GET）

配置或变更回调 URL 时，企业微信发起一次 GET 校验请求，携带 `msg_signature`、`timestamp`、`nonce`、`echostr`（加密随机串）。Bridge 完成验签后解密 `echostr`，将明文原样作为 HTTP 响应体返回；企业微信校验通过后，该回调地址生效。

#### 6.2.4 解密（消息保密与完整性前提）

业务推送（POST）中的消息正文以 AES 密文传输，密钥由 `EncodingAESKey` 派生。验签通过后：

1. 使用 EncodingAESKey 派生密钥解密 `Encrypt`。  
2. 得到明文消息（含 `corp_id`、`userid`、消息类型、文本或 `media_id` 等）。  
3. Bridge 仅基于明文进入身份链接查询与后续建任务流程。

效果：未持有 EncodingAESKey 的第三方无法还原业务内容；密文被篡改时验签失败或解密失败，均不得进入业务路径。

#### 6.2.5 与机器账号鉴权的边界

| 机制 | 保护区段 |
| --- | --- |
| Token 验签 + EncodingAESKey 解密 | 企业微信平台 → WeCom Bridge 的回调入站 |
| Bridge 机器账号（Basic Auth 等） | WeCom Bridge → Agent Forge 的 API 出站 |

两段凭证相互独立：回调验签不替代 Agent Forge API 认证；机器账号密码不参与企业微信回调签名计算。

```text
企业微信  --(msg_signature + 密文)-->  Bridge  --(Basic Auth + 业务 tenant/owner)-->  Agent Forge
              验签 → 解密 → 业务处理              机器账号证明「调用方为 Bridge」
```

### 6.3 调用主体矩阵

| 调用主体 | 企业微信回调 | Agent Forge API | 控制台确认页 |
| --- | --- | --- | --- |
| 匿名外网客户端 | 否（验签失败） | 否（无凭证 → 401） | 否（无有效 ticket） |
| 不可见 / 已禁用成员 | 可达回调但业务拒绝 | 不创建业务会话 | 不签发业务 ticket |
| 可见且 active 成员 | 经企微平台转发 | 不直接调用；由 Bridge 代调 | 仅持有本人任务 ticket |
| WeCom Bridge | 作为回调接收方 | 是（机器账号） | 作为 ticket 签发方 |
| 运维人员 | 否 | 按组织账号与 RBAC | 按组织账号与 RBAC |

### 6.4 Bridge → Agent Forge 调用约定

1. Bridge 使用专用服务账号完成 HTTP 认证。  
2. 可选：将该服务账号通过 `AGENTFORGE_IDENTITY_MAP` 绑定为固定机器身份，防止作用域头被外部伪造覆盖服务账号自身绑定。  
3. 创建业务会话 / 协作运行时，Bridge **显式传入**链接表中的业务 `tenant_id`、`owner_id`（及所需 role），使任务归属落在终端成员而非机器账号。  
4. 业务成员不分配、不告知 Agent Forge API 密码。

### 6.5 确认深链（ticket）

| 属性 | 要求 |
| --- | --- |
| 载荷 | `tenant_id`、`owner_id`、`session_id` 和/或 `run_id`、过期时间、签名 |
| 时效 | 短时有效；过期后须重新自企微入口获取 |
| 权限边界 | 仅打开所绑定任务的确认视图；不作为通用管理凭证 |
| 传输 | HTTPS；避免在不受控渠道长期转发 |

### 6.6 安全基线

- 回调 URL 仅暴露必要路径；管理端口与 Agent Forge API 不对公网无差别开放。  
- 应用 Secret、回调 Token / EncodingAESKey、机器账号密码、ticket 签名密钥纳入密钥管理，支持轮换。  
- 全链路保留：企微消息 ID、userid、AF session/run ID、操作者、时间戳，满足审计追溯。  
- 失败路径返回固定业务文案，不回显内部堆栈与密钥材料。  
- 验签失败或解密失败的请求不得创建会话、不得写入业务附件。

## 7. WeCom Bridge 功能设计

### 7.1 入站处理流水线

```text
企微回调
  → 验签 / 解密
  → 解析 corp_id、userid、消息类型、media_id / 文本
  → 查询 wecom_identity_link（必要时规则兜底 upsert）
  → status≠active 则出站拒绝文案并结束
  → 下载媒体（如有）并写入约定附件存储
  → 调用 Agent Forge：创建 session / 挂附件 / 启动对应协作
  → 出站 L0 受理（含任务号）
  → 订阅或轮询协作状态 → 映射为 L1/L2 出站
  → HITL 待办 → 签发 ticket 深链并出站
```

### 7.2 出站消息分级

| 级别 | 内容 | 是否推送企业微信 |
| --- | --- | --- |
| L0 受理 | 已接收、任务号 | 是 |
| L1 阶段 | 提取 / 匹配 / 待确认等短状态 | 是 |
| L2 摘要 | 草稿完成说明或风险摘要要点 | 是 |
| L3 全文 | 控制台产物链接 | 仅 URL，全文在控制台 |
| L4 轨迹 | 模型推理与工具调用细节 | 否 |

### 7.3 对外接口面（逻辑）

| 接口面 | 方向 | 说明 |
| --- | --- | --- |
| 企微回调接收 | 入 | 符合企业微信回调规范 |
| 企微通讯录 / 素材 / 应用消息 API | 出 | 使用应用 AgentId + Secret |
| Agent Forge HTTP API | 出 | 会话、附件、协作、状态 |
| 确认深链兑换 | 入（控制台侧） | 校验 ticket 后打开绑定会话 |

具体路径、字段与 OpenAPI 在实现阶段出接口说明书。

### 7.4 非功能要求（建议指标，实施时核定）

| 项 | 建议 |
| --- | --- |
| 回调响应 | 在企业微信要求的时限内完成验签与快速应答；耗时业务异步化 |
| 幂等 | 同一企微消息 ID 不重复创建业务任务 |
| 文件限制 | 遵循企微单文件大小与类型限制；超限明确提示 |
| 可用性 | Bridge 与 Agent Forge 分健康检查；依赖降级策略预定义 |
| 可观测 | 结构化日志 + 关键指标（回调成功率、建任务成功率、出站失败率） |

## 8. 运维与变更流程

### 8.1 上线检查清单

1. 自建应用创建完成；回调、Secret、可见范围配置正确。  
2. 通讯录只读或成员变更事件权限就绪（或已执行第 5.4 节过渡导入）。  
3. `corp_id` ↔ `af_tenant_id`、默认角色、机器账号、例外表写入配置。  
4. 全量同步完成；抽样校验 `af_owner_id` 符合生成规则且 `status=active`。  
5. 端到端：可见成员上传样例文件 → L0 → 控制台可见对应 owner 会话。  
6. 负向：不可见或 disabled 成员无法建任务。

### 8.2 日常变更

| 变更 | 操作入口 | 系统行为 |
| --- | --- | --- |
| 新增可用人员 | 企微：入职并纳入应用可见范围 | 同步或事件 → 自动建链 |
| 停用人员 | 企微：离职或移出可见范围；或例外表强制 disabled | 链接失效，后续消息拒绝 |
| 调整审批人 | 例外表角色覆盖 | 不改变 `owner_id` 生成规则 |
| 轮换密钥 | 配置中心 / 密钥库 | 按变更窗口滚动 |

### 8.3 与销售易身份衔接（后期）

扩展链：`userid` → `af_owner_id` → 销售易用户主键。  
优先采用工号、企业邮箱或 IdP subject 自动对齐；无法对齐的个案进入例外处理。SSO 方案在 S4 勘察后单独立项。

## 9. 验收标准（本设计范围）

| 编号 | 验收项 |
| --- | --- |
| A1 | 主入口为企业微信自建应用会话，而非群 Webhook 机器人主路径 |
| A2 | Bridge 独立部署；Agent Forge 内核无企微回调协议实现 |
| A3 | `af_owner_id` 符合 `wecom:{corp_id}:{userid}`；抽样与全量规则一致 |
| A4 | 通讯录同步（或等价过渡导入）后，可见成员可建任务；disabled / 不可见成员不可建任务 |
| A5 | 匿名请求无法调用 Agent Forge API；业务用户无 API 密码分发记录 |
| A6 | ticket 仅能打开绑定 session/run，过期失效 |
| A7 | 企微出站无 L4 级推理轨迹；L0 含任务号 |
| A8 | 审计可关联 userid、owner_id、session/run、时间 |

## 10. 风险与依赖

| 风险 / 依赖 | 影响 | 应对 |
| --- | --- | --- |
| 通讯录权限开通周期 | 延迟自动同步 | 启用第 5.4 节过渡导入 + 消息兜底 |
| 企微文件大小与类型限制 | 大附件失败 | 前置提示；约定拆分或网盘策略（另评） |
| 回调超时 | 企微重试 / 用户无即时回执 | 快速 ACK + 异步处理；幂等去重 |
| 密钥泄露 | 伪造回调或盗用 API | 密钥轮换、网络隔离、审计告警 |
| 销售易账号模型差异 | S4 身份对齐失败 | 接口勘察后再定对齐键 |

## 11. 术语

| 术语 | 定义 |
| --- | --- |
| WeCom Bridge | 企业微信与 Agent Forge 之间的对接服务 |
| wecom_identity_link | 企微成员与 AF 租户/归属/角色的链接物化表 |
| Token | 企微回调验签口令，与 EncodingAESKey 一并在应用回调配置中设置 |
| EncodingAESKey | 企微回调消息 AES 密钥材料，用于加解密消息体 |
| msg_signature | 企微回调请求中的签名字段，供 Bridge 与本地计算结果比对 |
| 机器账号 | 仅供 Bridge 调用 Agent Forge 的服务凭证 |
| ticket | Bridge 签发的短时确认深链令牌 |
| HITL | 人工确认闸门 |
