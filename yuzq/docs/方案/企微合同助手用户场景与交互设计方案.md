# 雨中情 · 企业微信合同助手用户场景与交互设计方案

| 项 | 内容 |
| --- | --- |
| 文档性质 | 对外业务与交互设计说明 |
| 适用对象 | 客户销售管理 / 销管业务评审 |
| 版本日期 | 2026-10-31 |
| 产品入口名称（建议） | 合同助手（企业微信工作台应用） |
| 范围边界 | 本文描述用户角色、业务场景、端到端流程与界面交互规范。身份对接与系统安全见《企微身份映射与对接服务设计方案》。销售易字段级对接以接口勘察结论为准 |

## 1. 设计目标与产品定位

### 1.1 业务目标

| 目标 | 说明 |
| --- | --- |
| 缩短会审前录入耗时 | 销售以合同原件（PDF / Word / 图片）发起智能预填，减少在 CRM 中逐项手录 |
| 前移校验闸门 | 物料候选、缺件、关键字段在提交会审前完成确认，降低会审后退回重录成本 |
| 降低跨角色沟通成本 | 会审意见形成后，输出业务视角的风险后果说明，供领导与业务阅读 |
| 贴合现有办公习惯 | 以企业微信为日常触点；关键确认在结构化确认页完成 |

### 1.2 产品定位

合同助手是嵌入企业微信的**合同智能作业入口**：接收材料、反馈进度、送达待办与结果摘要。  
合同要素的结构化确认、物料选择与草稿审阅在**确认工作台**完成。  
企业既有**会审审批链**（法务 → 办事处经理 → 商务等）保持不变；本产品不替代会审权限与签批责任。

### 1.3 能力分期（对业务可见）

| 阶段 | 业务可感知能力 |
| --- | --- |
| 第一期 · 智能录入 | 企微提交合同 → 进度通知 → 确认预填草稿 → 按现有流程发起会审 |
| 第二期 · 评审参考（可选） | 对已确认草稿生成分层评审参考卡，供会审人阅读 |
| 第三期 · 会审后业务风险 | 提交会审意见后，生成「签署该条款对公司业务后果」类摘要与依据入口 |
| 第四期 · CRM 贯通 | 确认后的约定字段写入销售易合同模块 |

首期演示与试点可不依赖销售易写回；草稿确认后由业务按现行方式进入会审。

### 1.4 明确不纳入本产品决策范围的事项

- 不自动写入销售易或替代人工确认。  
- 不替代法务、商务、办事处经理的会审签批。  
- 不输出「建议签署 / 不建议签署」类结论。  
- 不承担印章、建单、发货指令等执行系统职责。

## 2. 用户角色与权限观感

| 角色 | 典型岗位 | 在合同助手中的主要行为 |
| --- | --- | --- |
| 录入发起人 | 一线销售 / 销管录入岗 | 上传合同、补充说明、确认预填与物料候选、查看草稿状态 |
| 会审参与人 | 法务、办事处经理、商务、大区等 | 在既有会审系统中审批；可选阅读评审参考卡；会审后可触发业务风险报告 |
| 业务阅览人 | 销管负责人、分管领导 | 阅读风险摘要与依据，用于决策参考 |
| 应用管理员 | 企微管理员 / IT | 配置应用可见人员范围（谁能使用合同助手） |

权限观感原则：

- 用户仅处理本人发起或被授权确认的任务。  
- 不同人员的任务列表与确认页相互隔离。  
- 管理员通过企业微信应用可见范围控制可用人员，业务侧无「单独开通一套账号」的日常手续。

## 3. 信息架构

### 3.1 双表面结构

| 表面 | 载体 | 承担职能 |
| --- | --- | --- |
| 会话表面 | 企业微信 · 合同助手应用会话 | 提交材料、接收受理与进度、接收待办与结果摘要、打开确认链接 |
| 确认表面 | 确认工作台（浏览器 / 企微内置浏览器） | 结构化字段确认、物料候选选择、缺件补录、草稿审阅、风险报告全文与依据 |

会话表面强调**短、少、可行动**；确认表面强调**完整、可核对、可回退修改后再确认**。

### 3.2 任务对象

每一次有效提交形成一条**合同任务**，对用户展示：

| 属性 | 说明 |
| --- | --- |
| 任务号 | 受理后立即可见，用于沟通与排查 |
| 当前阶段 | 如：接收中 / 提取中 / 匹配中 / 待确认 / 已出草稿 / 风险生成中 / 已完成 / 失败 |
| 发起人 | 当前企业微信使用者 |
| 关联材料 | 已上传的合同文件列表 |
| 待办类型 | 如：确认物料、补全缺件、确认草稿、阅览风险 |

## 4. 核心用户场景

### 场景 A · 会审前智能录入（第一期主路径）

**触发**：销售取得客户合同文本（PDF / Word / 扫描件或拍照）。  
**价值**：生成带出处的预填草稿与物料候选，经销售确认后再进入会审。

| 步骤 | 用户行为 | 系统反馈 |
| --- | --- | --- |
| A1 | 企业微信工作台打开「合同助手」 | 进入与应用的一对一会话 |
| A2 | 发送合同文件；可选发送简短说明（合同类型、项目名等） | 回复受理消息，含任务号 |
| A3 | 等待处理 | 阶段性进度消息（条数受控） |
| A4 | 收到「待确认」消息，点击「去确认」 | 打开确认工作台，进入本任务 |
| A5 | 逐项核对预填字段；对物料候选做选择；补全缺件 | 界面即时校验必填与格式 |
| A6 | 确认提交草稿 | 会话收到草稿完成摘要；任务阶段更新为已出草稿 |
| A7 | 按公司现行流程将合同提交会审 | 本阶段不自动写销售易（第四期前） |

### 场景 B · 缺件补录与候选选择

**触发**：合同未覆盖系统必填项，或物料名称与主数据不一致。  
**价值**：在会审前闭环信息缺口。

| 步骤 | 用户行为 | 系统反馈 |
| --- | --- | --- |
| B1 | 在确认页查看「待补全」列表 | 每项标明：字段名、为何必填、合同中是否出现 |
| B2 | 补录文本或选择日期/枚举 | 保存为待确认草稿值 |
| B3 | 在物料行查看候选列表（近似匹配） | 展示标准物料名与区分信息，供单选 |
| B4 | 无合适候选时标记「未匹配 / 需人工建档」 | 任务可继续，但该行进入明确待办状态，不静默假匹配 |

### 场景 C · 会审中参考评审卡（可选第二期）

**触发**：草稿已确认，会审人需要结构化参考。  
**价值**：分层展示基础核对与条款标注，不替代会签意见。

| 步骤 | 用户行为 | 系统反馈 |
| --- | --- | --- |
| C1 | 授权角色打开评审参考入口（会话链接或工作台任务） | 展示评审参考卡 |
| C2 | 按基础 / 技术 / 商务 / 法务分层阅读 | 每条含事项、说明、依据入口；无「可签/不可签」结论 |
| C3 | 在既有会审系统中填写会审意见 | 会审意见的权威落点仍在客户审批系统 |

### 场景 D · 会审后业务风险评估（第三期）

**触发**：会审意见已形成，领导需要业务后果说明。  
**价值**：将条款与意见转写为「若按此执行，对公司回款、质保、调价、敞口等意味着什么」。

| 步骤 | 用户行为 | 系统反馈 |
| --- | --- | --- |
| D1 | 在合同助手提交或关联「会审意见」及合同引用 | 受理并生成任务号（或关联原任务） |
| D2 | 等待生成 | 阶段进度消息 |
| D3 | 阅读会话内风险摘要（区分赊销 / 现款等场景标签） | 摘要为业务语言，若干要点 |
| D4 | 需要时打开全文与依据 | 展示条款出处、历史或规则依据；未命中处标注「无法判断」 |
| D5 | 将报告作为决策参考材料使用 | 不出现签署建议句式 |

### 场景 E · 确认后写入销售易（第四期）

**触发**：草稿已人工确认且字段映射勘察完成。  
**价值**：减少二次录入。

| 步骤 | 用户行为 | 系统反馈 |
| --- | --- | --- |
| E1 | 在确认页执行「写入销售易」或等价动作（须再次确认） | 仅写入允许字段清单 |
| E2 | 查看写入结果 | 成功回执含 CRM 单据定位信息；失败可重试并保留原因 |

### 场景 F · 异常与拒绝

| 情形 | 用户侧表现 |
| --- | --- |
| 文件格式或大小不符合要求 | 明确失败原因与建议（更换格式、压缩、拆分） |
| 处理超时 | 补发「仍在处理」类进度；超时失败给出固定失败说明与任务号 |
| 无权限使用应用 | 企微侧不可见应用，或会话内拒绝文案 |
| 缺少会审意见即请求风险报告 | 拒绝启动或要求补传意见（产品默认：要件不齐不生成正式风险卡） |

## 6. 交互规范 · 企业微信会话表面

### 6.1 入口与首屏

| 要素 | 规范 |
| --- | --- |
| 入口位置 | 企业微信工作台 → 合同助手 |
| 会话形态 | 用户与应用的一对一会话（非群 @ 机器人主路径） |
| 首屏引导（建议） | 三行内说明：支持的文件类型；发送文件即可开始；重要确认将在确认页完成 |
| 指令负担 | 不要求用户记忆斜杠命令；自然语言短句与文件投递均可受理 |

### 6.2 消息类型与文案层级

| 类型 | 目的 | 文案要求 |
| --- | --- | --- |
| 受理 | 建立信任与可追溯 | 含任务号；说明已收到何种材料 |
| 进度 | 降低等待焦虑 | 短句；对应业务阶段；控制推送频次，避免刷屏 |
| 待办 | 驱动行动 | 明确待办类型 + 单一主按钮「去确认」 |
| 结果 | 闭环感知 | 草稿完成或风险摘要要点；提供「查看全文」入口 |
| 失败 | 可恢复 | 原因可读、下一步可执行、保留任务号 |

### 6.3 禁止默认推送到会话的内容

- 模型推理过程、内部工具名称、原始 JSON、调试置信度字段。  
- 超长合同全文或整表字段倾泻。  
- 无行动点的重复进度（除超时安抚类单次补发）。

### 6.4 会话内按钮与链接

| 控件 | 行为 |
| --- | --- |
| 去确认 | 打开本任务确认工作台；链接短时有效，失效后提示自会话重新获取 |
| 查看全文 / 查看风险报告 | 打开只读或确认态全文页 |
| 再次提交材料 | 作为补充附件关联至原任务或按规则开新任务（实现时二选一，须在文案中声明） |

### 6.5 多任务并行

- 同一用户可存在多个进行中任务。  
- 进度与待办消息须带任务号或合同简称，避免混淆。  
- 确认链接必须绑定到具体任务，禁止「打开后还要猜是哪一单」。

## 7. 交互规范 · 确认工作台

### 7.1 页面布局原则

| 区域 | 内容 |
| --- | --- |
| 顶栏 | 任务号、合同简称/文件名、当前阶段、发起人 |
| 主区 · 字段确认 | 分组展示预填项：字段名、预填值、出处（合同页码/段落或报价行）、编辑控件 |
| 主区 · 物料清单 | 行项目、候选列表、匹配状态 |
| 主区 · 缺件 | 待补全清单与录入区 |
| 侧栏或底栏（按分辨率自适应） | 原始附件预览入口、保存、确认提交、返回会话说明 |
| 风险报告页（三期） | 摘要、场景标签、分条后果、依据列表、无法判断项 |

桌面与手机均需可用：手机优先单列；附件预览可采用「新页打开」。

### 7.2 字段确认交互

| 规则 | 说明 |
| --- | --- |
| 有出处才预填 | 无出处字段保持空或「待补」，不得伪装为已提取成功 |
| 出处可见 | 用户可查看该值来自合同何处，便于核对 |
| 分组对齐业务表单 | 建议对齐现行销售易五大块：基础信息、管理信息、标的明细、付款条件、收货与授权 |
| 确认粒度 | 首期支持整单确认；对高风险字段可要求显式勾选「已核对」 |
| 保存与提交 | 「保存」不改变会审资格；「确认提交」后草稿进入已确认态 |

### 7.3 物料候选交互

| 规则 | 说明 |
| --- | --- |
| 候选数量 | 每行展示有限条最相近标准物料（如 Top-3），避免长列表压迫 |
| 信息充分 | 候选项展示足以区分配置差异的主数据属性（名称、规格要点等，以主数据实际字段为准） |
| 选择反馈 | 选中态清晰；支持改选 |
| 无法匹配 | 提供明确出口，进入人工后续，不强制选错 |

### 7.4 缺件追问交互

| 规则 | 说明 |
| --- | --- |
| 列表优先 | 一次性列出本任务全部缺件，减少来回跳转 |
| 原因可读 | 区分「合同未写」与「系统必填」 |
| 阻塞策略 | 关键缺件未完成时，「确认提交」不可用并提示剩余项 |

### 7.5 会审后风险报告交互（三期）

| 模块 | 要求 |
| --- | --- |
| 场景标签 | 标明赊销 / 现款等适用场景；同条款在不同场景下的提示可并存但须区分 |
| 业务后果 | 使用业务语言描述回款、质保、调价、敞口等影响；可引用毛利与资信等已知输入 |
| 依据 | 每条可回溯至条款位置、内部规则或历史合同条目；无依据则标注「无法判断」 |
| 禁语 | 不出现替代人决策的签署建议 |

### 7.6 状态与反馈

| 状态 | 界面表现 |
| --- | --- |
| 加载中 | 骨架屏或进度，禁止空白无说明 |
| 保存成功 / 失败 | 非阻断轻提示；失败可重试 |
| 确认成功 | 明确成功页或成功态 + 引导返回企微或进入会审说明 |
| 票据过期 | 说明原因，引导自合同助手会话重新打开 |

## 8. 关键界面文案规范（示例框架）

正式上线文案须经客户销管确认；以下为结构示例。

### 8.1 受理

> 已收到《{文件名}》，任务号 {任务号}。正在提取合同要素，完成后将通知您确认。

### 8.2 进度

> 任务 {任务号}：正在匹配物料清单。  
> 任务 {任务号}：仍有 {N} 项信息待您确认。

### 8.3 待办

> 任务 {任务号} 待确认：请核对预填字段并选择物料候选。  
> [去确认]

### 8.4 草稿完成

> 任务 {任务号} 草稿已确认。请按公司流程提交会审。  
> [查看草稿]

### 8.5 风险摘要导语

> 任务 {任务号} 业务风险摘要（场景：赊销）已生成。以下为要点，详细依据请查看全文。  
> [查看风险报告]

### 8.6 失败

> 任务 {任务号} 未能完成：{原因}。您可重新发送文件或联系管理员，并提供本任务号。

## 9. 内容与合规约束（交互层）

| 约束 | 交互体现 |
| --- | --- |
| 人机责任分离 | 所有生效前动作须显式确认；按钮文案避免「自动生效」暗示 |
| 依据优先于断言 | 确认页与风险页突出出处与依据入口 |
| 会审主权不变 | 文案称「参考」「摘要」，不称「审批通过」 |
| 隐私与隔离 | 界面不展示他人任务；转发确认链接时提示时效与本人任务属性 |

## 10. 验收要点（业务与交互）

| 编号 | 验收项 |
| --- | --- |
| U1 | 授权销售可从工作台进入合同助手并完成上传 → 受理 → 确认 → 草稿可见 |
| U2 | 会话消息含任务号；进度不超过约定频次；无内部调试信息 |

| U6 | 风险报告（若启用）含场景区分与依据/无法判断；无签署建议句 |
