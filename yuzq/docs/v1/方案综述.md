# 方案综述：雨中情防水技术集团

> **面向企业的多智能体协作，在运行时上把业务自动做起来。**
>
> 这句话落到雨中情，只有一种验证方式：把「合同到件 → 结构化 → 首轮审查 → 派单」和「标书/讲标素材」这两段真实业务，拆成有名字、有边界、有交接物的岗位，让 agent 在运行时按规则协作，让人只在关键节点签发——并且每一步事后都查得到。造、跑、治理、观测是这件事的能力底座与工作方式，不是对外的一句话主张。
>
> 文档性质：**内部研究稿，非对外定稿**。Agent Forge 与雨中情防水技术集团**不存在**合作、签约或交付关系；文中效益数字全部为假设，不构成 ROI 或交付承诺。

## 一、客户要点（均有公开来源，证据级别见附件）

- **基本盘**：创始于 2000 年，总部陕西西安高陵，主营建筑防水材料研发、生产、销售及防水工程施工；新三板挂牌（874922，基础层，2025-11-03），注册资本 2 亿元，挂牌披露员工 556 人（统计口径待核）。来源：官网·公司概况、东方财富 F10。
- **渠道结构**：官网自述「全国 7 大工厂 + 42 个办事处 + 500 多家服务网点」，但生产基地页实际列出 6 个基地（西安、咸阳、兰州、泰州、潍坊、富平）——**7 与 6 的口径差异必须由品牌部确认**，否则写进任何对外材料都是硬伤。
- **客户结构**：中国建筑、中国铁建、中国交建、陕西建工等央国企总包的供应商；参建西成高铁、银西高铁、西安地铁、陕西奥体中心等。→ 推断：订单呈「大客户、大项目、集采」特征，框架协议 + 集采订单 + 项目合同多层并存，合同版本多样。
- **销售组织**：官网销售网点页可见「西安直销」与多地「××办」；销售人员在册数量**未检索到公开来源**，不得用行业比例估算。
- **能力落差已被制度承认**：2026-05 举办「五星评定」通关，流程含现场讲标呈现，经理级需完成销售政策制度笔试（官网 2026-05-19）。→ 说明讲标/标书是核心能力抓手，销售政策是显性考核项。
- **数字化底座不明**：ERP、MES、CRM、CLM、电子签、OCR 均**未检索到公开来源**；仅 2018 年有泛微协同 OA 合作报道（二手，深链待核）。这是方案形态的第一约束。
- **行业环境**：2026 年 1—9 月房地产开发投资 -20.6%、新开工 -24.9%、到位资金 -21.6%（国内贷款 -33.1%），二手房网签 +10.7%（国家统计局）。→ 新建缩量、增量转向基建市政与存量修缮、甲方付款能力下降推高合同风险密度。

## 二、痛点：两段业务性质完全不同，不能一套打法

| 编号  | 痛点                                             | 适配判断                                                    |
| ----- | ------------------------------------------------ | ----------------------------------------------------------- |
| P2/P4 | 合同评审负荷与法务人力不匹配；结论不留痕、难回溯 | **强对齐**：多岗位分工 + 冲突升级 + 逐条挂原文，四问全过    |
| P1    | 合同以照片/扫描件到件，结构化录入靠人            | **适合**：抽取 + 交叉校验，人只校差异；但**不做零人工入库** |
| P3    | 多法人多区域，模板/授权/用印口径分散             | **部分适合**：要件核对可自动化，授权与用印批准必须留人      |
| P6    | 销售能力参差，讲标与标书生产靠个人               | **部分适合**：多角色供料 + 一致性校验，销售定稿与讲标       |
| P7    | 销售政策有文本、难查准、执行不一致               | **部分适合**：问答可自动，解释权与例外批准在人              |
| P8    | 报价与让利依赖个人经验                           | **不宜硬上**：只做取数与越界提示，定价由人拍板              |

**明确排除**：出具法律意见与责任认定、用印批准与授权授予、最终报价与让利、经销返利/账期授信/区域价格政策测算、以「多 agent」为卖点的空壳编排、CRM/ERP 重系统替换。

排序逻辑：先修进料口（P1），再修判断口（P2 为主叙事）；优先选「判断标准已写成文字」的环节；合同链路落点是文件 + 审批流，比销售链路（依赖 CRM 回写）风险更低，故先做。

## 三、方案与 POC 切口

协作形状（借自行业案例的**形状**，不借其数字）：到件段用 **pipeline**（收件 → 抽取 → 校验 → 催办，上下游互不信任、以原件为唯一依据）；审查段用 **supervisor**（合同主办拆活，商务/质保/资质/用印四个审阅员并行，冲突不由 agent 折中，升级法务）；标书段用 **pipeline + 校验闸门**（虚构业绩一票否决）。

**HITL 是运行时的一等状态，不是事后补签**：HITL-1 差异确认（录入岗）、HITL-2 审查结论签发（法务终审人）、HITL-3 例外偏离批准（法务负责人）、HITL-4 用印（既有 OA，不进 agent 决策）、HITL-5 派单确认、HITL-6 标书定稿、HITL-7 playbook 变更。

| POC                                    | 范围                                                        | 周期（假设）              | 硬验收指标                                              |
| -------------------------------------- | ----------------------------------------------------------- | ------------------------- | ------------------------------------------------------- |
| **POC-1** 合同到件 → 结构化 → 差异清单 | 单主体、1 类高频合同；不含用印、不含对外发送                | 4–6 周                    | **静默错误 = 0**；高后果字段一致率；人工复核耗时降幅    |
| **POC-2** 合同首轮审查 + 留痕          | 单主体、2–3 类合同；出偏离项与建议，不出法律意见            | 6–8 周                    | **结论可回溯原文 100%**；覆盖率、法务采纳率、红线漏检率 |
| **POC-3** 标书/讲标素材供料            | 解析 → 业绩匹配（只读库）→ 段落初稿 → 偏离核对 → 一致性校验 | 6–8 周（建库另加 2–4 周） | **虚构业绩放行 = 0**；素材可溯源 100%；制作工时降幅     |

**POC-1 与 POC-2 必须串行**（审查输入质量取决于结构化契约），POC-3 可并行但依赖销售侧 champion。先做 2 周摸底，5 个阻塞项无结论则不进入 POC。

## 四、效益假设：数字很小，所以不拿降本当卖点

以「每 100 份合同」测算（全部为占位假设 H1–H9，无一条客户实测）：录入 `(35−12) 分钟 × 80 份 ≈ 30.7 小时`，审查 `(90−70) 分钟 × 100 份 ≈ 33.3 小时`，合计毛节省 ≈ 64 小时 ≈ 8 人日；按 800 元/人日折算约 6,400 元/百份，扣 40% 复核与运维后 ≈ **3,840 元/百份（纯算术示例）**。标书按年 20 份、省 1 人日/份 ≈ 16,000 元/年（毛）。

未计入 OCR 回退、缺件催办、法务返工、集成与运维——**净效益可能显著低于示例，甚至为负**。因此真正的价值主张在非财务侧：**留痕可回溯、口径统一、风险前置、新人上手、审计应对**。POC 验收看「质量 + 可追溯 + 采纳率」，不看省了多少钱；效益数字对外出现时必须同时标注「假设、非承诺、须以 POC 实测为准」。

## 五、风险与待核

**七个风险点**：① 法务定责边界（agent 输出=内部审阅辅助，不构成法律意见）；② 合同数据敏感（自托管、按主体划权，未答合规要求前不做架构承诺）；③ 抽取误判（低置信强制标黄、静默错误即熔断）；④ 使用意愿（嵌进现有入口，不新开系统；按大区设种子用户）；⑤ 集成条件（只叠加不替换既有 OA）；⑥ 口径被放大（playbook 与对外口径表单一事实源，冲突必须升级）；⑦ 证据级别误用（业界案例不得写成自有客户，案例数字不得当预期）。

**五个阻塞项（不答不能开工）**：① 年合同份数、页数、扫描件占比；② 法务审核时长、驳回率、层级；③ 现有系统清单（OA/ERP/CRM/合同/电子签）及集成方式；④ 销售人员总数与区域分布；⑤ 数据安全/等保/信创要求与是否允许外部模型调用。另需确认：法务人数与模板数、playbook 是否存在、用印授权规则、是否有 CLM/OCR、标书量与工时、基地口径（7 还是 6）、556 人统计时点。

**证据边界**：本次检索未找到「建材行业多智能体 + 合同审查 + 销售赋能」一体化落地的一手公开案例（国内防水/建材方向仅有服务商软文）。故本方案是**形状推理**，不是「同行已验证」的复制——对外沟通不得包装成行业已验证。
