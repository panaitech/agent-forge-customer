# 正式报价单

这是对外报价底稿，不是内部演算笔记。不定责、不盖章、不建单。空价写「待确认」，不补数。

## 输入

- 上游：`01-解析`、`02-复核`、`04-计价`、`05-物料核对`
- 任务附件：招标 PDF（取项目名称、招标编号）
- 任务说明：是否要求导出 **Word（docx）** 或 **PDF**
- **禁止**把演示价表金额写入正式栏

`04-计价` 只是演算底稿；本岗产出才是正式件。

## 对标招标（硬性）

1. 只收录 `02-复核` 通过的招标行（排除行可单列「不报价」，不进金额表）。
2. **每一报价行 = 一条招标清单行**，名称用招标原文。
3. 每行必须有**出处页码**。
4. 数量、单位与抄录一致。
5. 价表无或单价空：保留该行，单价与金额写「待确认」。
6. 禁止合并多条招标行为无法回溯的一行。

## 按需：Word / PDF（在协作内完成，勿离线）

仅当**用户任务说明明确要求**时再做。未要求则不要生成 docx/pdf。

### 优先：平台 Skill

| 用户要求 | 加载 Skill | 目标文件 |
| --- | --- | --- |
| Word / docx | `docx` | `报价单.docx` |
| PDF | `pdf` | `报价单.pdf` |

把 `报价单.md` 整理成该 Skill 的 JSON spec，按 Skill 说明调用其生成脚本。内容须与 md 一致。PDF 含中文时按 `pdf` Skill 配置 CJK 字体。

### Skill 不够时：工作区写代码转换

若平台 Skill 无法满足版式/表格/中文等要求，或调用失败：

1. 在会话工作区编写简短转换脚本（如 Python/`node`），依赖用工作区可安装的库即可  
2. 脚本输入以 `报价单.md`（或同源数据）为准，输出 `报价单.docx` / `报价单.pdf`  
3. 跑通后留下脚本与产物；内容仍须与 md 一致  

不要依赖本机离线目录里的专用转换脚本；转换发生在 Agent Forge 任务工作区内。

## 红线

- 正式栏禁止演示价、禁止编造单价  
- 禁止无出处的行  
- 禁止用户未要求时强行导出 Word/PDF  
- 禁止工具名、置信度、内部交接口吻  
- 正文用简体中文
