# calc.py —— 创迪情报板专用计价计算器

> 本文说明 `scripts/calc.py` 的定位、输入来源、计算逻辑与输出去向。阅读本文前先记住一句话：**大模型负责「选」，本脚本负责「算」。**

---

## 一、它是什么

`calc.py` 是整条「创迪-情报板报价」协作链上**唯一**的计算权威。

| 角色 | 做什么 | 不做什么 |
| --- | --- | --- |
| 大模型（计价员） | 读招标书和价目表，判断每条屏的形态、尺寸、选哪一行单价、钢构归谁 | 不做任何乘除、不产出一个金额 |
| `calc.py` | 拿到模型选好的 JSON，算出面积、块数、每项金额、价链、总价 | 不读文件、不碰 Excel/PDF、不判断业务 |

为什么要这样拆：让**所有算术只有一个出处**，模型推理再快再慢都不会算错数字；也让成本同事可以直接拿脚本核对每一处公式。

---

## 二、输入：`lines.json` 从哪来、长什么样

输入不是脚本自己读的，是**大模型从三份上游文档提炼、写成 JSON 喂给脚本**的。

```
招标书(PDF 或上轮解析稿) ──解析员──► 01-解析.md（哪条屏、尺寸、形态、出处）
规格单价表 + 核算口径表 ──读表员──► 03-读表.md（模组宽高、单价、辅材、支架、控制箱汇总）
            01 再由复核员核对 ──► 02-复核.md（通过的条目）
                            │
                            ▼
        计价员读 01/02/03，逐条「选」好参数，写成 lines.json
                            │
                            ▼
                 python3 calc.py < lines.json   ← 计算器
```

### 顶层结构

```json
{
  "control_base": 3018.75,
  "chain": { "coef": 1.03, "div": 0.68, "card_n": 69, "card_d": 750, "ipc": 2980 },
  "lines": [ { /* 每条屏一套 */ } ]
}
```

- `control_base`：控制箱汇总金额（每套底数），来自 `03-读表.md`。
- `chain`：写死常数，来自创迪原表样例。通常用默认值，可省略。
- `lines`：逐条屏的观察结果。

### lines[] 每行 = 一套屏，字段分三类

**① 身份与形状**（模型从 `01-解析` 抄录）：

| 字段 | 含义 |
| --- | --- |
| `seq` | 招标序号 |
| `name` | 设备名称 |
| `qty` / `unit` | 招标数量 / 单位（单位仅备注，不参与计算） |
| `length` / `height` | 单幅长、高（米） |
| `panels` | 每套屏数（双幅 = 2） |

**② 选价**（模型从 `03-读表` 选行；没价或未定档填 `null`）：

| 字段 | 含义 |
| --- | --- |
| `module_w_mm` / `module_h_mm` / `module_price` | 模组宽高（毫米）与单价 |
| `box_per_m2` | 箱体元/㎡ |
| `power_price` / `power_per_m2` | 电源单价 / 每㎡只数（无维护值填 `null`） |
| `aux_per_m2`（或 `aux_lines`+`aux_div`+`aux_plus`） | 辅材元/㎡（汇总格有数填前者，为空才填明细） |
| `pack_per_m2`（同理） | 包材元/㎡ |
| `bracket_price` / `bracket_unit` | 支架单价 / 单位（单位仅备注） |
| `hoop_price` | 抱箍单价（无价填 `null`） |

**③ 口径判定**（模型按规则定）：

| 字段 | 含义 |
| --- | --- |
| `form` | 安装形态（天棚屏 / 门架1米 / 门架1.5-2米 / 悬臂 / 车道屏1米 / 车道屏1×2米 / 车道屏2×2米 / 服务区 / 洞内屏 / 小型情报板） |
| `side` / `side_given` | 面别（单面/双面）/ 是否招标写明面别 |
| `steel` | `"self"`（自己供，正常算支架）或 `"provided"`（交安已供整套钢构，支架抱箍为 0） |
| `hoop` | `"self"`（正常算抱箍）或 `"provided"`（清单写「含连接抱箍钢结构」） |
| `body` | 立柱/支座/门架横梁本体的说明（如「含立柱」），只进「未计入钢构」清单，不清支架 |

> **关键设计：`area`（面积）不在输入里**，模型禁止手填。面积由脚本按 `长 × 高 × 屏数` 自行计算，这是根治「屏体被重复乘数量」的核心手段。

## 三、计算逻辑

脚本分三段：**公式库 → 逐条计算 → 价链与总价**。

### 1. 公式库（纯函数，无副作用）

| 函数 | 职责 | 公式 |
| --- | --- | --- |
| `down(n)` | 向下取整（带浮点容差） | `floor(n + 1e-9)` |
| `money(n)` | 两位小数 | `round(n + 1e-9, 2)` |
| `bracket(form, l, h)` | 支架数量 | `len2`=长+2；`box`=长×高；`tunnel`=长÷2+1；`small`=长+1 |
| `cable(form, l, h)` | 大屏线材 | 天棚/门架1米=(长−10)×100；门架1.5-2米=(长−10)×150×高+(高−1)×300；服务区=长×高×50；其余 `None` |
| `cards(form, l, h)` | 接收卡数量 | 天棚/悬臂/门架/服务区=(长÷2)×高；小型=1；其余=高 |
| `control(form, l, h, base)` | 控制系统 | 门架1.5-2米=base+(高−1)×100+(长−5)×100；服务区=base+(高−1)×300+(长−5)×200；其余=base |
| `per_sq(...)` | 辅材/包材元/㎡ | 有汇总格直接用，否则 Σ(明细单价×数量)÷div+常数 |
| `num(row, key)` | 读可空数字 | `None` → 「待确认」 |

### 2. `one()` —— 逐条算单套

对 `lines[]` 每一行执行，顺序：

1. 校验形态 → `area = length × height × panels`。
2. 模组块数 = 面积 ÷ 单块面积，向下取整；单价 `null` 则金额「待确认」。
3. 箱体/电源/辅材/包材 = 元/㎡（或元/只）× 面积（或只数）。
4. 支架：`steel == "provided"` 才为 0，否则按形态公式 × 单价。
5. 抱箍：每套 1 只；交安已供 / 清单写含抱箍钢构 / 无价目 → 0。
6. 线材、接收卡：**永远**按形态公式算，不随钢构清零。
7. 控制系统：每套底数 + 形态加价。
8. 屏体小计 = 模组+箱体+电源+辅材+包材；平方单价 = 屏体小计÷面积；屏体合计 = 屏体小计 + 线材。

### 3. `chain_row()` + `main()` —— 价链与总价

- `chain_row()`：在单套屏体合计基础上套创迪价链：
  - 基础合计 = 屏体合计 + 支架 + 抱箍 + 控制系统 + 普通接收卡(数量×69)
  - 普通综合价格 = 基础合计 × 1.03
  - 含点检综合价格 = (屏体+支架+抱箍+控制+点检接收卡 数量×750) × 1.03
  - 含工控机和点检综合价格 = (基础合计 + 工控机 2980) × 1.03
  - 三档综合报价 = 对应综合价格 ÷ 0.68
- `main()`：读 stdin JSON → 逐条算 → 打印三张 Markdown 表：
  1. **分项收口（单套）**：每个分项的数量与金额；
  2. **综合价链与三档报价（单套）**；
  3. **三档总价** = Σ(综合报价 × 数量)。

## 四、输出：给谁、怎么用

```
calc.py stdout ──► 04-计价.md ──► 报价单员照抄 ──► 报价单.md
```

- 计价员把 stdout 三张表**原样抄进 `04-计价.md`**，禁止改任何一个数，再在表后补每条模组定档与钢构归属备注。
- 报价单员**不再算任何金额**，只把 `04` 的数字按招标序号拼进正式表头，补上名称/规格/出处。
- 整条链上金额只有一个产生点：`calc.py`。

## 五、一个最小例子

序号 1「悬臂式可变情报板（含立柱）」13 套，模型填：

```json
{"seq":"118-1","name":"悬臂式可变情报板（含立柱）","qty":13,"unit":"套",
 "form":"悬臂","length":3.2,"height":1.6,"panels":1,
 "side":"单面","side_given":false,
 "module_w_mm":200,"module_h_mm":200,"module_price":null,
 "box_per_m2":870,"power_price":72,"power_per_m2":null,
 "aux_per_m2":445.0435,"pack_per_m2":16,
 "bracket_price":230,"bracket_unit":"套","hoop_price":25,
 "steel":"self","hoop":"self","body":"含立柱"}
```

脚本算出这一套：

| 分项 | 算式 | 结果 |
| --- | --- | --- |
| 面积 | 3.2 × 1.6 × 1 | 5.12 ㎡ |
| 模组块数 | 5.12 ÷ (0.2×0.2) | 128 块（单价 null → 待确认） |
| 箱体 | 870 × 5.12 | 4,454.40 |
| 电源 | 2只/㎡ × 5.12 = 10.24 → 取整 | 10 只 × 72 = 720.00 |
| 辅材 | 445.0435 × 5.12 | 2,278.62 |
| 包材 | 16 × 5.12 | 81.92 |
| 屏体小计 | 4454.40+720+2278.62+81.92 | 7,534.94 |
| 支架 | 悬臂 长×高=5.12 → 取整 | 5 只 × 230 = 1,150.00 |
| 抱箍 | 每套 1 只 | 1 × 25 = 25.00 |
| 线材 | 悬臂无线材公式 | — |
| 接收卡 | (3.2÷2)×1.6 = 2.56 → 取整 | 2 |
| 控制系统 | 悬臂无加价 | 3,018.75 |
| 基础合计 | 7534.94+1150+25+3018.75+2×69 | 11,866.69 |
| 普通综合报价 | 11866.69 × 1.03 ÷ 0.68 | 17,974.55（单套） |

本行合计 = 17,974.55 × 13 套，进入三档总价累加。

## 六、业务规则出处

- 形态 → 支架/线材/接收卡/控制系统公式：`方案/原表公式与经验配量确认.md`（第四节「常规产品报价单按安装形态」）。
- 写死常数 69 / 750 / 1.03 / 0.68 / 工控机 2980：同上（第四节 + 确认项 F）。
- 双幅不乘屏数、未写面别按单面、电源无维护值 2 只/㎡、含立柱/含支座/附着既有的钢构口径：`方案/场景演示建议口径.md`。

这些是**创迪业务层**，不是通用计价引擎。换客户/品类时，公式层（`KIND` + 各 `bracket/cable/cards/control` + 默认值）需要重写，只有「stdin JSON → stdout Markdown + 单套粒度 + 价链框架」这一层骨架可复用。
