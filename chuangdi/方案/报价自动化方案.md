# 创迪情报板报价自动化方案（内部底稿）

本文件供内部对齐使用。创迪的产品是高速公路上的情报板。方案说明产品怎么分、两张核算表各管什么、需求与痛点落在哪，以及为什么用岗位型 Agent 协作把报价做完。取价、数量和金额的口径是成本岗的经验，写成 skill，由计价岗按 skill 执行。任意 PDF 都可以解析，每次解析附带一份解析指令。文中的招标文件只是指令的一个例子。金蝶云星空可以授权只读查询；POC 不连接客户账套，自建一个接口相近的模拟服务。

> 使用边界
>
> - 截至本文，双方未签约、未上线。本文不构成交付承诺。
> - 事实来自 2026-10-28 会议纪要、会后微信、客户提供的两张表。招标文件《中铁云南建设投资有限公司重庆市武隆至两江新区高速公路（平桥至大顺段）情报板、火灾报警系统及紧急电话与有线广播、视频监控系统、弱电系统集成采购招标》（招标编号 ZTYTWLGS-2026-04）只作为解析示例，不代表系统只认这一份 PDF。
> - 供应商名称和真实采购单价不写入本文。第三节的演示价只供内部 demo，不得用于对外报价。
> - 第八节是按上述材料做的理解示例，未经客户核对，不能当作创迪的正式报价。
> - 年报价单量、参与核算人数、平均单表工时，会议约定下次沟通再补，本文留空。

## 原则：人继续维护价格

报价用的单价仍由成本维护人在表里改。灯珠单价、加工费、套件、箱体单价、辅料的每平方米用量，都由人填写、人调价。系统不生成这些数，也不代替人决定什么时候涨价。

人继续在自己的电脑上用 Excel 维护价格，维护的是整理后的价格表：一行一个规格。供应商名称只留在本机那张表里，不随任务上传。Agent Forge 跑在云端，读不到这台电脑上的目录。报价时，人把这一次要用的文件随任务交给对应的岗。云端只读这次任务里的文件，不访问本机其他路径。单价不再抄进核算表，也不再把整本成本同步给另外一两个人。

大模组核算原表是客户造价/应标演算底稿。整理后拆成 Agent 三件套：**规格单价表**（模组等大件单价）+ **核算口径表**（辅材 BOM、每平米收口结构、箱体/电源/支架/抱箍价目）+ **计价 skill**（公式骨架）。辅料由 BOM 汇总成元/㎡ 再 × 面积。  
项目报价由 Agent **按本项目重算收口分项并出报价单**，不是「样例每平米收口 × 招标面积」。原件留在 `docs/`，不覆盖。口径见 [场景演示建议口径.md](场景演示建议口径.md)、[原表公式与经验配量确认.md](原表公式与经验配量确认.md)。

取价、数量和金额怎么算，写成 skill，由计价岗执行，并在结果里附上算式。成本岗改：规格单价表、核算口径表（BOM 与价目）、以及这份 skill。**程序里不另放一套算法**（POC 已去掉 `price.py` 规则重算）。

## 一、产品形式

创迪做情报板，也就是高速公路上的可变情报板。门架、悬臂、隧道拱顶、车道、服务区是同一产品的安装位置和尺寸，共用一套模组、箱体、电源和辅料算法。

同一份招标文件里还有火灾报警、视频监控、车道指示器、信号灯、电光标志、雾灯和收费门架。那些行不属于创迪的产品，本方案不报价、不展开。

### 1.1 标准品与非标品

| 类别 | 判断 | 工作量 |
| --- | --- | --- |
| 标准品 | 安装形态、点间距、配比、箱体开闭在企业价格表和核算表里已有成行 | 按模板展开。会议说明常规产品不逐条回 ERP 复核 |
| 非标品（定制品） | 显示面积、安装方式、亮度或箱体超出成行组合，需要按面积重算模组数量 | 大型项目里定制比例约 70%–80%。完成一份报价至少约 4 小时（会议口径为 3–4 小时） |

新建项目和改造项目的成本路径不同。两张样例表里没有这条规则，标为待核。

### 1.2 安装形态

核算表里已经按这些形态分开计价。每种仍是情报板。

| 形态 | 清单里常见写法 | 成本上要分开的部分 |
| --- | --- | --- |
| 门架式 | 跨单幅或跨双幅，含或不含立柱 | 屏体、立柱、抱箍。双幅是一套里的两块屏 |
| 悬臂式 | 含情报板立柱，或不含基础预埋件 | 屏体加立柱或支座 |
| 附着交安门架 | 钢结构由交安提供，含连接抱箍 | 只计屏体和抱箍，不计交安钢结构 |
| 隧道内拱顶 | 含控制箱、支架；清单可能写双基色 | 洞内箱体、控制箱、支架 |
| 车道屏、服务区、信息发布 | 服务区或停车区，含支座或嵌入标志板 | 屏体加对应安装件。嵌入式标志和整块情报板在价格表里不是同一行 |

差别落在这些参数上：显示面积、点间距、配比、亮度、驱动芯片、箱体（压铸铝或铁箱，全密封或后开放，含或不含包边，是否洞内）、灌胶（单面或双面）、以及是否含立柱、抱箍、支架、控制箱。基础预埋件在样例清单里多次写明不含，报价不含这一项。

### 1.3 参数从哪一章来

解析对象是任意 PDF。Agent 不预设某一份招标文件的章节。每次任务附带解析指令，写明产品范围、清单所在位置、技术参数所在位置、按什么名称把参数对齐到清单行、哪些行排除。没有指令时不解析。

下面这张表是示例文件 ZTYTWLGS-2026-04 的指令内容，不是解析器的固定规则。在这份文件里，需求一览表只提供名称、显示面积、数量和含不含立柱、抱箍；点间距、亮度和防护等级在附件四《技术评分标准》（印页第 61 页，包件 QBB），按物资名称取用，并保留页码。换一份 PDF 时，改指令，不改解析岗位。

| 附件四条款 | 已写明的参数 |
| --- | --- |
| 门架式可变情报板 | 点间距 31.25mm；每平方米亮度不低于 8000cd；防护等级 IP65 |
| 悬臂式可变情报板 | 点间距 25mm；发光亮度不低于每平方米 8000cd；防护等级 IP65 |
| 隧道内拱顶可变情报板 | 静态视认距离不小于 200 米，动态视认距离不小于 150 米；显示亮度不低于每平方米 5000cd。未写点间距 |
| 信息发布可变情报板（嵌入式可变情报板） | 像素分辨率每平方米 15625；发光亮度不低于每平方米 6500cd。未写成毫米级点间距 |

配比、芯片、灌胶、灯珠批次和辅料，招标书不写。应标人用本企业价格表里满足上述点间距、亮度和防护等级的默认行来选型，辅料按核算表的每平方米用量计入。这是投标人选型，要在结果上标明，不能写成招标文件原文。

## 二、两张表的关系

两张表没有互相引用。单价靠人工从价格表抄进核算表。

### 2.1 材料成本表：规格单价

文件：`docs/材料成本.xlsx`。它回答「这一档模组、箱体或套件的含税单价从哪一行来」。

工作表：

| 工作表 | 作用 |
| --- | --- |
| 普通模组价格（按驱动芯片分两表） | 常规模组尺寸的规格行。同一张表左右两块是两个灯珠批次 |
| 250×500 模组价格（同样按驱动芯片分两表） | 模组尺寸为 250×500 的规格行 |
| 灯价格 | 分色灯珠单价和部分灯型单价。样例中的灯珠单价已清零 |
| 折叠屏模组、强力 | 样例中基本为空 |
| 箱体单价 | 按箱体名称、外形尺寸、密封方式和是否包边列单价 |
| 套件 | 按点间距列底壳、面罩、胶圈，合成套件单价 |

一行规格的键是：点间距 × 配比 × 芯片 × 亮度 × 尺寸 × 色品 × 灯珠批次。单面/双面灌胶同属一行，用两列含税单价区分；报价时按核算模板的灌胶面别选列。

含税单价的构成写在计价 skill 里：单面＝灯珠数量 × 分色单价 + 加工费 + 套件；双面＝单面 + 灌胶加价。本文不记录系数。

### 2.2 大模组核算表：造价演算底稿

文件：`docs/大模组核算2026.06.16.xls`。客户原工作簿，叠了辅材 BOM、每平米收口、零件价目、控制箱 BOM、屏体清单样例。整理结果见 `数据/核算口径表.xlsx`（辅材、每平米收口结构、箱体/电源/支架/抱箍/控制箱价目）。公式链见 [核算原表计算规则分析.md](核算原表计算规则分析.md)；维护见 [核算口径表维护说明.md](核算口径表维护说明.md)。报价单「控制系统」取控制箱汇总（每套）及形态加价，见报价单 skill。

本项目收口顺序（与原表同构，数字重算）：

1. 模组：规格表宽高 + 招标面积推算块数（演示除不尽向下取整）；单价取规格表。
2. 箱体：核算口径「箱体」元/㎡ 进入平方单价构成；规格表物理箱仅核对。
3. 电源：价目取核算口径；只数取已确认/演示维护定额或 question。
4. 辅材/包材：BOM 汇总元/㎡ × 面积。
5. 报价单层：支架/线材/接收卡/工控机/综合价链按原表样例做法，代入本项目尺寸（演示建议沿用 69/750、1.03、0.68 等）。

招标以抄录面积为准，不绑原屏体清单样例长宽。

### 2.3 和金蝶 BOM 的分工

金蝶云星空里的 BOM 比 Excel 辅材表更完整。报价核对只对大件（模组、箱体等）；辅材不逐颗对金蝶。万芳确认：常规产品不会定期把 Excel 大件逐条回金蝶核对。

因此三份数据各管一段：

| 数据 | 负责 |
| --- | --- |
| 规格单价表（自材料成本） | 模组等大件规格单价；物理箱 SKU 核对。供应商留在本地不提交 |
| 核算口径表（自大模组核算） | 辅材 BOM；收口结构；箱体元/㎡与电源/支架/抱箍价目；经验数量须确认后才作默认 |
| 物料查询（POC 为模拟服务） | 大件编码是否存在、规格是否一致。只读抽查。正式环境可换成已授权的金蝶云星空 |

采购单价通常在采购价目表，不在 BOM 上。价目表的表单标识以创迪账套元数据为准，常见写法是 `PUR_PriceCategory`，标为待核。

## 三、表结构整理与演示工作簿

可行性对照之前，先把两张表整理成可提交形态。整理结果：**规格单价表**（一行一规格）与 **核算口径表**（BOM + 收口结构 + 价目）。模组单价由灯珠、加工费和套件合成。辅料由 BOM 汇总成元/㎡ 再 × 面积。单价、BOM、价目由人维护；项目收口由 Agent 重算。客户原件不动，整理结果和演示价另存。

请客户按 [模版/报价数据整理模版.xlsx](../模版/报价数据整理模版.xlsx) 填写，步骤见 [模版/填写说明.md](../模版/填写说明.md)。黄色示例行要改成真实数据或删除。

可运行的对照实现在 [poc/README.md](../poc/README.md)。它按岗位生成交接；**金额按计价 skill 由 Agent 计算，程序不另写一套算法**。大件走模拟查询。演示用 `数据/规格单价表-演示.xlsx` 与 `数据/核算口径表-演示.xlsx`（`seed_demo.py` 自正式/原表整理稿填入模拟价），不是客户成本。核算口径维护见 [核算口径表维护说明.md](核算口径表维护说明.md)。

### 3.1 材料成本表改成一行一个规格

点间距、配比、芯片、亮度、尺寸、色品、灯珠批次各占一列。单面灌胶和双面灌胶合为一行，用「含税单价_单面」「含税单价_双面」两列；便于人维护，报价时由 skill 按核算模板的灌胶面别选列。现在同一工作表左右各放一个灯珠批次，整理时拆成行，避免两套批次规格挤在同一行的左右列里。

普通模组和 250×500 模组合并为一张模组价格表，用尺寸列区分。箱体、套件、灯珠单价仍分表，每张表只留一套表头。灯珠分色单价、加工费、套件单价、灌胶加价作为输入。含税单价用公式计算：灯珠合计等于各色数量乘各色单价，单面含税单价等于灯珠合计加加工费加套件，双面含税单价等于单面含税单价加灌胶加价。

调价时直接改该行单价，不另起历史行，不维护「是否当前」「生效日期」。供应商名称放在单独的内部表，报价检索不读那一列。折叠屏模组、强力两张空表不纳入。

### 3.2 核算表改成安装形态模板

一行对应一种情报板默认选型：安装形态、点间距、模组尺寸、箱体类型、每平方米电源数量、每平方米接收卡数量、是否含立柱、抱箍、支架、控制箱。模组单价不写死在这里，报价时到规格单价表取值。若仍有「每平方米辅料」列，须与核算口径表 BOM 滚出值一致，不一致以 BOM 为准。双幅的块数、交安已提供的钢结构是否计价，做成明确字段。

### 3.3 样例里的价格还原不了

客户交来的材料成本表里，灯珠分色单价已被清空。灯珠合计和单面含税单价用公式引用这些单价，结果跟着是 0。双面列的公式是在单面单价上再加一个灌胶常数，常数还在，但没有灯珠成本时，这个常数不是模组价格。部分加工费单元格仍有数字。箱体单价列和套件合计列是空的。灯价格表的分色单价也是空的。

残留的加工费和灌胶常数只说明公式还在，不能反推出灯珠单价，也不能还原真实采购价。

### 3.4 另建演示工作簿

后续 demo 需要非零金额才能把一条清单走到报价草稿。做法是另建「规格单价表-演示」「核算口径表-演示」，不覆盖正式整理稿与客户原件。

- 规格行、灯珠数量、含税单价公式和灌胶加价方式沿用原表。
- 被清空的灯珠分色单价、加工费、箱体单价、套件单价填入演示数。演示数只为让公式出非零结果，并让不同点间距、不同配比之间有差距，便于看出命中的是哪一行。
- 文件名、表头和报价草稿页眉都写明「演示价，不得用于对外报价，不代表创迪成本」。
- 正式核算口径表不抄演示大件单价。报价时按点间距和尺寸到规格单价表（或演示副本）取数。辅料取核算口径 BOM 汇总；演示副本可对空单价补模拟数。
- 真实单价仍等客户在本地补一版数值自洽的脱敏表。演示价不拿去衡量金额准确率。金额可复算只表示：同一套演示价重复计算，结果相同。

## 四、需求整理

下面每条都可以单独验收。

| 编号 | 需求 | 验收时看什么 |
| --- | --- | --- |
| R1 | 按当次解析指令，从任意 PDF 读出情报板行：名称、显示面积、数量、含不含立柱、抱箍、支架、控制箱，以及钢结构是否由他人提供 | 字段能回到页码和原文。无指令时拒绝解析 |
| R2 | 技术参数的取值位置写在解析指令里，按指令中的对齐方式取用，带来源 | 用示例文件时，门架、悬臂两类与第 61 页条款一致。换文件时按新指令验收 |
| R3 | 名称不能逐字对齐时，给出归并建议并标明，不把归并写成招标原文 | 附着交安门架、信息发布、预告标志三类有明确处置 |
| R4 | 用点间距、亮度、防护等级到人维护的价格表里找出对得上的模组。配比、芯片、灌胶用企业平时常用的行，标明「投标人选型」 | 能指回价格表的哪一行。同时对上多行时不自动挑最低价 |
| R5 | 标准品按核算模板选型。非标按显示面积和模组尺寸算模组数量。辅料按 BOM 汇总元/㎡ × 面积，标明来源于 BOM | 双幅按块数计价。交安已提供的钢结构不计价 |
| R6 | 大件到物料查询服务只读核对是否存在、规格是否一致、是否禁用。POC 调用自建模拟服务 | 不一致时升级给销售，不改价、不写回。模拟服务与金蝶单据查询的入参形态相近 |
| R7 | 供应商表不进入任何岗位。解析岗不读价格表。计价岗按 skill 只读取本行命中的当前单价，并在结果中写出算式 | 越权测试下，解析岗的输入中没有价格表；任何岗位的输入中没有供应商表 |
| R8 | 报价单行结构跟随该项目的需求一览表，输出投标明细价格表 | 行序、名称、单位、数量与清单一致。缺参数的行留空并标原因 |
| R9 | 可自动采纳的行达到 90%，其余行必须标出由人确认。漏标算失败 | 用脱敏历史单分层统计：参数抽取、型号匹配、BOM 完整性、金额可复算 |
| R10 | 金额由计价岗按 skill 中的算式计算，结果附算式。同一抄录、同一价格行、同一份 skill，人重算得到同一金额 | 金额按算式复算验收，不按模型准确率验收 |

会议里业务方曾用模型直接生成报价表，准确率约 70%–80%，后面仍要大量改。R9 的 90% 指「可以采纳的行」加上「其余行都被标出来」，不是要求模型独自写对整张表。

## 五、痛点与解法

每一条都写明现行做法的后果，以及本方案用哪一步接住。解法的实现位置见第七节。路径为什么这样选，见第六节。

| 编号 | 现象 | 后果 | 解法 |
| --- | --- | --- | --- |
| P1 | 点间距、配比、尺寸、灌胶、箱体的组合很多。大型项目约 70%–80% 是定制 | 非标一单至少约 4 小时，依赖个别有经验的人 | 先从招标文件里取出已经写明的点间距和显示面积，再按这些条件到价格表里找出对得上的模组，从很多行里剩下一行或少数几行。配比和芯片招标书没写，用企业平时常用的那一行，并标明是投标人选的。表里对不上的行标出来，有经验的人只确认这些行 |
| P2 | 价格表和核算表没有链接，单价靠人抄 | 灯珠调价后，核算表可能仍用旧单价 | 人仍然只维护价格表。核算模板里不写单价，只写「用哪一种模组」。报价时按点间距、尺寸等条件去价格表取对得上的那一行。调价只改价格表该行单价，下一次报价用新价 |
| P3 | 核算表的大件和金蝶 BOM 会漂移。常规产品不定期复核 | 编码或规格已变时，报价仍按旧表 | 报价前用物料查询服务按编码和规格做只读核对，结果为不一致、禁用或无此料时升级给销售，不沿用旧行。POC 查的是模拟服务里的本地大件；客户授权金蝶之后，同一查询改打云星空。辅料不做逐颗核对 |
| P4 | Excel 辅材是逐项 BOM，对外报价乘面积；金蝶 BOM 更细 | 若报价时逐颗对金蝶，口径与工时都会失控 | 辅料按核算口径表 BOM 汇总出的元/㎡ × 面积，标明来源于 BOM 汇总。物料查询只核对模组、箱体等大件 |
| P5 | 单价经常变。2–3 人使用同一套表，其中 1 人维护后再同步。表不上公网 | 共享表格会泄露供应商和成本，所以现在不能靠在线表格协作 | 仍由这一位成本维护人在本地改价格表。报价时只取出单价，不把供应商名称给到模型和报价岗。另外一两个人不再接收整本成本表 |
| P6 | 设计院清单写安装和面积，评分标准写点间距和亮度，两处不在同一页 | 只读清单会漏参数；把评分条款套到名称不同的行上会报错规格 | 解析指令写明清单位置和技术参数位置，以及按物资名称对齐。指令没写的章节不读。名称对不上时标成归并或未命中，不套用邻近条款 |
| P7 | 直接让模型出整张报价表 | 会议反馈准确率约 70%–80%，异常点也不集中 | 解析岗只交出抄录和页码，复核岗对照原文页。取价、数量、金额按成本岗写在 skill 里的口径执行，算式随结果给出。可自动采纳的行与必须人工确认的行分开列出，漏标算失败 |

新建与改造的差价规则未在样例中出现，不列入已证实痛点，标为待核。确认规则之后，在核算模板里分开两行算法，单价仍到人维护的价格表里取。

## 六、为什么走 Agent 协作

本节比较四条路径。结论是：报价由岗位型 Agent 协作完成。选择这条路径的理由有三条：推理与自适应、专家经验沉淀、反馈评审可视化。取价、数量和金额的口径写成 skill，由计价岗按 skill 执行。下面先写选择时不作为依据的部分，再按这三条展开。

### 6.1 四条路径

| 路径 | 实际在做什么 |
| --- | --- |
| 人工 | 有经验的人阅读设计院清单和评分标准，在价格表、核算表里找行，抄单价，算块数和金额 |
| 固定脚本 | 把已经见过的版式、已经写清的取价和算式做成程序。同一输入得到同一输出 |
| 单模型出整表 | 把招标文件和价格材料交给一个模型，一次生成报价 |
| Agent 协作 | 解析岗按指令交出抄录和页码。复核岗只拿抄录和原文页核对，对不上就退回。计价岗按成本岗写在 skill 里的口径取当前价、算数量、算金额，并写出算式。销售确认被退回的行 |

有四件事，固定脚本和 Agent 协作都能做，不作为选择依据：按条件取价格行；同一条件多行时列出候选，不挑最低价；不读取供应商表；把待确认的行单独标出。这些是报价必须守住的规矩，两条路径都可以守住。

### 6.2 三条理由

**推理与自适应。** 报价表的行结构跟随设计院。大型项目里定制约占 70%–80%，栏位、换行和名称写法按项目变。固定脚本要求先有人看过这一份表，把「名字断开时怎么接」「数量写在名字的哪一侧」写成规则。规则没有写到的地方，相邻行的数字仍会进入金额。可行性对照里，按招标编号 ZTYTWLGS-2026-04 写成的读取规则，曾把上一行的 13 套计到下一行，修正规则之后才分开。下一份设计院的表不在这套规则里。解析岗按当次指令推理：清单在哪一章、点间距在哪一章、这个名称该对齐哪一条评分条款、双幅是几块屏、钢结构是谁提供的。指令换了，读法跟着换，不必为每一份新表改程序。复核岗不参与这次推理，只用原文页否决。单模型也能当场读，但读和算在同一次生成里，读错的数会直接变成金额。会议里这种出整表的做法，准确率约 70%–80%，异常点不集中。

**专家经验沉淀。** 一块屏拆成几块模组、双幅按几块计、交安已经提供的钢结构计不计、辅料按每平方米估算还是按颗展开、同一点间距有多行时留哪一行，这些是成本岗的经验，现在靠人记住，也散在两张没有互相引用的表里。写进程序之后，成本岗看不到，也改不了。价格表里的单价可以调，程序里的数量口径还是旧的，两套口径会分开走。skill 把这套经验写成成本岗能审阅、能修改的作业说明。计价岗只按说明取当前行、算块数、算金额。人用同一份说明和同一价格行可以重算。口径要改时，改 skill，不改程序。新建与改造的差价尚未在样例里出现，确认之前不写进 skill，标为待核。人一旦不在，下一次报价仍有这份文本可依。成本岗继续维护价格数字和这份 skill。

**反馈、评审与可视化。** 每一行的结果放在同一张报价草稿上：出处页码、命中的是价格表哪一行、数量怎么拆的、算式、物料核对是四种结果里的哪一种、本行是自动采纳还是待确认、待确认的原因。销售按行看，只确认被退回的行，不用重读整份招标书，也不用打开价格表。退回写明停在抄录、选行还是算式，只重做那一岗。缺页码、缺算式、价格行多于一行，这一岗视为没有交付。这样评审看到的是过程，整张表的对错可以指到具体的一行和具体的一步。

### 6.3 技术侧

| 比较项 | 人工 | 固定脚本 | 单模型出整表 | Agent 协作 |
| --- | --- | --- | --- | --- |
| 未见过的设计院清单 | 人当场阅读 | 先改读取程序，再跑 | 模型当场阅读，抄录和金额在同一次输出里 | 解析岗按指令阅读。复核岗用原文页否决。否决的行不进入计价 |
| 计价口径由谁改 | 成本岗口头传授，或改旧表 | 改程序并发版 | 当次生成自行决定 | 成本岗改 skill。计价岗按当前 skill 执行 |
| 单价和供应商出现在哪 | 整本表在维护人处。同步给他人时，供应商和成本一起离开本机 | 程序可以读全表，输出时再裁剪 | 生成报价的同一次上下文里带着价格材料 | 解析岗不读价格表。计价岗只读本行命中的当前单价。供应商表不进入任何一岗 |
| 错误停在哪一步 | 靠同一个人自己发现 | 停在已经写过的规则上。没写过的情况仍会算出一个数 | 停在成稿上，分不出抄录、选行和算术 | 停在抄录、选行或算式这三张交接之一。只重做该岗 |
| 金额如何验收 | 人再算一遍 | 程序重复运行，结果相同 | 不能把生成准确率当成金额正确 | 结果附算式。按同一 skill、同一价格行重算，应得到同一金额 |
| 自动采纳 | 没有这一档 | 可以按写死的条件放行 | 猜出来的行和按口径算出的行混在一起 | 点间距有出处、价格行唯一、数量关系清楚、物料核对为一致，四条同时成立才放行。其余行必须标出 |

实现上同时守住这些约束：

- 交接缺页码、缺算式，或同一条件的当前价格行多于一行，这一岗视为没有交付，退回重做。多行时列出候选，不挑最低价。
- 复核岗不改抄录中的数字，只判定原文页是否支持这个数。
- 计价岗不改点间距，不在 skill 之外换一种算法。配比、芯片来自企业常用行时，结果标明投标人选型。
- 辅料/包材按 skill：BOM 汇总出的元/㎡ × 面积，标明来源于 BOM 汇总。电源、接收卡若规格单价表没有单价，只列数量，金额不计入。
- 物料核对仍是只读查询，结果写进交接。不一致、禁用、无此料的行不进入自动采纳，也不写回物料服务。
- 模型不得用概数代替算式。金额按算式复算验收，不按模型准确率验收。

某一类设计院的版式如果长期不变，并且该类清单上的抄录已经反复与原文页一致，这一段阅读可以收成固定程序。计价口径仍留在 skill 里，因为改口径的人是成本岗。现在设计院清单和新建、改造的差价都还没到可以收成程序的程度。

### 6.4 结论

报价走 Agent 协作，理由是推理与自适应、专家经验沉淀、反馈评审可视化。解析岗按指令阅读没见过的设计院清单，复核岗用原文页否决。skill 承接成本岗关于取价、数量和金额的经验，计价岗按 skill 执行。报价草稿把页码、价格行、算式和待确认原因放在每一行上，销售按行评审。单价仍由人在价格表里维护。供应商表不参与报价。

## 七、落地

不用知识库，也不把整份 PDF 和整本价格表交给同一个模型生成报价。各岗只收到这次任务里交给它的文件。解析岗按当次指令从 PDF 取出清单行和技术参数，复核岗对照原文页。计价岗按 skill 取当前价格、算数量、算金额。大件核对走物料查询服务，不从 Excel 里读 BOM。

部署在创迪可控制的环境。供应商表留在成本岗本机，不上传。任务怎么分岗、文件落在哪，见 [poc/业务流程.md](../poc/业务流程.md)。

### 7.0 文件怎么交给 Agent

云端读不到创迪电脑上的路径。人在本机改完表，报价时把文件随任务提交。提交之后，这份文件只在这次任务里。本机绝对路径不作为读法。

| 交给谁 | 这次任务里的文件 | 不提交的内容 |
| --- | --- | --- |
| 解析岗 | 招标 PDF，当次解析指令 | 价格表、成本表、供应商表 |
| 复核岗 | 解析岗的抄录，以及抄录点名的原文页 | 价格表 |
| 计价岗 | 按模版整理的价格表、成本表、计价 skill | 供应商表 |
| 物料核对 | 大件的名称和规格 | 不收 Excel。向 BOM 服务查询 |

计价岗读 Excel 时，在交接里写明：文件名、工作表名、表头在第几行、用了哪些列、模组有几行。评审能看见这张表是按哪些列读的。读不到任务里的文件时，这一岗退回，不改用本机路径。

BOM 服务不在 Excel 里，也不在创迪那台电脑的磁盘上。它是任务能访问的只读地址。POC 用自建模拟服务，表单名仍是 `ENG_BOM` 与 `BD_MATERIAL`。客户授权金蝶之后，把这个地址换成云星空。Agent 只发查询，不打开金蝶所在的机器。

```mermaid
flowchart LR
  pdf[任意PDF加解析指令] --> parse[解析岗交出抄录和页码]
  parse --> check[复核岗对照原文页]
  check --> price[计价岗按skill取价并写算式]
  price --> query[模拟服务只读核对大件]
  query --> gate{行是否可自动采纳}
  gate -->|可采纳| draft[报价草稿]
  gate -->|需复核| human[销售确认]
  human --> draft
  draft --> sheet[按清单结构出明细价格表]
```

### 7.1 岗位与边界

| 岗位 | 输入 | 输出 | 边界 |
| --- | --- | --- | --- |
| 清单解析 | 任意 PDF，外加当次解析指令 | 每一行的名称、面积、数量、含项、点间距、亮度、防护等级，以及出处页码 | 不读价格表。指令未写明的章节不读取。没有同名条款时标待确认，不套用邻近条款 |
| 原文复核 | 抄录，加上出处页的原文 | 通过，或退回并写明原文里缺哪个数 | 不改抄录中的数字，不取价，不算金额 |
| 计价 | 已通过复核的抄录、任务里提交的价格表和成本表、计价 skill | 命中的价格行、读了哪张表哪一列、数量、算式、金额；或未命中及原因 | 只读这次任务里的文件。只按 skill 执行。多行命中时列出候选，不挑最低价。供应商表不在提交文件中 |
| 物料核对 | 大件的名称和规格 | 一致 / 不一致 / 禁用 / 无此料；不一致或禁用时附带主数据候选（编码、名称、规格、禁用状态），不含单价与供应商 | 只读。POC 只调模拟服务，不写回 |
| 报价装配 | 清单行序、算式和核对结果 | 投标明细价格表 | 行结构跟随该项目清单。待确认行留空并写原因 |

规格匹配、模组块数、箱体数量、辅材/包材（BOM→元/㎡→×面积）和灌胶加价都写在计价 skill 里，不另设一套程序算法。skill 由成本岗维护。

人工闸门有两处。销售确认名称归并、缺项和「投标人选型」。成本维护人单独更新本地单价和计价 skill。Agent 不写回物料服务。

解析指令至少包括五项：产品范围（本次只收情报板）、清单表的识别方式、技术参数所在位置、名称对齐规则、排除规则。示例文件的指令是：清单取第五章需求一览表，点间距和亮度取附件四中与物资名称相同的条款，名称不完全相同的行标成归并，信号灯、车道指示器、雾灯、收费门架排除。另一份 PDF 换一份指令。

### 7.2 物料查询：金蝶可授权，POC 用模拟服务

金蝶云星空可以授权第三方只读查询。登录用 `AuthService.ValidateUser` 或 `AuthService.LoginByAppSecret`，单据查询用 `DynamicFormService.ExecuteBillQuery`。物料清单的表单标识是 `ENG_BOM`，可取父项、子项、用量和规格；物料主数据的表单标识是 `BD_MATERIAL`。创迪这套账套是否已经开通，不作为 POC 的前置条件。

POC 自建一个只读模拟服务，数据来自整理后的本地物料和 BOM，由两张表里的大件生成。调用形态与金蝶单据查询相近：传入表单标识、过滤条件和字段列表，返回行。表单仍用 `ENG_BOM` 与 `BD_MATERIAL` 这两个名字，便于以后把同一客户端指到已授权的金蝶地址。模拟服务不保存供应商和采购单价。

核对结果只有四种：一致、不一致、禁用、无此料。后三种交给销售；**不一致或禁用时须带上账套物料候选（编码、名称、规格、禁用），便于销售核对，不得只回一个状态词**。仍不返回采购单价与供应商。采购价目表不接到模型侧。客户授权金蝶之后，再把查询地址从模拟服务换成云星空，字段以该账套元数据核对。这一步不在 POC 演示范围内。

### 7.3 什么叫自动采纳

一行同时满足下面四条，才进入自动采纳：

1. 点间距来自当次解析指令指定的位置，出处页码完整。用示例文件时，该位置是附件四的同名条款。
2. 价格表在该点间距、亮度和企业默认配比、芯片下只有一行。
3. 数量关系清楚。双幅已按块拆开，他人提供的钢结构已剔除。
4. 模拟服务对大件的核对结果为一致。服务未包含该大件时，结果为无此料，该行不进入自动采纳。

名称归并、企业默认的配比或芯片、辅料估算，都标成可复核。历史脱敏单上的目标是：可自动采纳的行达到 90%，其余行全部被标出。漏标算失败。金额按 skill 里的算式复算。单表工时另行记录，本文不写下降比例。

### 7.4 阶段

| 阶段 | 范围 | 开始条件 |
