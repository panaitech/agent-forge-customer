## 二、痛点清单（6 条）

> 排序见第四节。每条只回答「是什么、为什么难、谁痛」，适配判断放第三节。

### P1｜标准版本多、状态在变，换版影响面算不清

**现象**

- 国内标准 699 项、IEC 34 项、IEA 课题 21 项同时在册；国内标准三年增长约六成（F8、F9）。
- 「已发布 / 参与」长期 80%–85%，意味着约 15%–20% 处于在研、报批或在途（F10）；同一时点存在「已发布版 / 在研版 / 被替代版」三种状态并存。
- 标准分国家、行业、地方团体四类，2026-06 未披露分项（F11）；2022 年还出现过总数与分项差 2 项的口径不一致（F14）。
- 换版后如何通知设计、工艺、采购、服务、培训，公开渠道查不到（G4）。

**影响**：一条标准换版，理论上要同时排查设计红线、供应商合同条款、手册、巡检项、课程五类载体。缺影响面清单，只能靠各部门自查，容易出现「设计已改、手册未改、课程仍旧」的错引；对外则是认证/投标引用过期条款的风险。

**上游依据**：画像 §2.2、§2.2 脚注、§4.1 判断二、§5 第 4 项；F8–F11、F14、G4。
**置信度**：**高**（版本多、状态在变是硬事实；「影响面算不清」的机制属判断，但 §4.1 已明确「作业链依赖人工维护文档，是知识断层的风险点」）。

---

### P2｜条款级检索缺失：任务发生时取不到「该用哪一条」

**现象**

- 标准被「拆出去」而非「存起来」：进入设计红线（F15）、供应商品类规则（F19）、合同准则（F20）、手册（F23）、巡检项（F24）、课程（F26），但没有一个以「标准」为管理对象的系统被公开证明存在（G1）。
- 画像 §4.2 明确列出四个未获公开回答的问题：工程师能否按「机型 + 国家 + 认证体系」检索条款；换版如何识别受影响机型/手册/合同/课程；投标偏离表如何对齐条款；新员工如何从 700 项中定位到本岗位那 20 项。
- 认证要同时满足国内与国际两套规则（F17、F18），「标准—机型—市场」三元对应关系需要维护，但无公开对照表（G3）。

**影响**：检索靠人找人、找文件夹、找老同事；新人上手周期长；同一问题不同人给出不同条款依据。这是「知识可得性」问题，不是「知识存量」问题——金风并不缺标准，缺的是任务上下文里的定位与引用。

**上游依据**：画像 §2.5 分析判断、§3 场景表第 1/3/5/8 行、§4.1 判断一、§4.2、§5 第 1/3 项；F15、F16、F19、F23、F24、G1、G3。
**置信度**：**中**（「嵌入式而非集中式」是画像明示的判断；条款级检索缺失=公开信息缺失，须访谈确认）。

---

### P3｜作业链最易失真：手册、课程、巡检项与标准不同步

**现象**

- 手册系统具备结构化编制与「一次生成、多次使用」能力（F23），但公开材料未说明版本同步机制（画像 §3.1(5)）。
- 培训侧有 304 门课程、253 名内训师、题库与能力测评（F26、F27），但没有课程与标准条目的映射（G7）。
- 巡检与工单已高度标准化（F24），但「判据阈值来自哪条标准、规则如何版本管理」未披露（画像 §3.1(4) 分析判断）。

**影响**：作业链是三条链路中唯一「弱约束」的一条（画像 §4.1 判断二），没有外部审计和合同罚则兜底。标准改版后，现场人员按旧手册操作、按旧题库考试、按旧判据巡检，错误不会被及时发现，直到出现不符合项或事故复盘。

**上游依据**：画像 §3 场景表第 9/10 行、§3.1(4)(5)、§4.1 判断二、§5 第 7 项；F23、F24、F26、F27、G7。
**置信度**：**中**（载体存在、能力存在是事实；「不同步」是画像推断，G7 未披露）。

### P4｜供应链准入靠人工比对证书与条款

**现象**

- 准入是长链条人工流程：开发、资料审核、考察、认证评分、产品试制、小批量验证、产品认证评分（F21）。
- 标准以「品类关联规则」形式嵌入采购（F19），准则要纳入合同（F20），绿色评价要现场 + 文件双审核五类核心部件（F22）。
- 画像 §4.3 直接判定：条款比对「工作量大、规则明确、可审计——适合人机协同」。

**影响**：单家供应商的评审要跨证书有效期、认证范围、品类标准、社会责任承诺多份材料；人工比对既慢又易漏（尤其证书过期、范围不符两类）。漏判的后果是有质量与合规责任的，不是体验问题。

**上游依据**：画像 §3 场景表第 5/6 行、§3.1(3)、§4.3 抓手 2；F19–F22。行业侧对照：案例 §六「供应链准入/证书核验」行、§七 第 1 条、§八「谨慎切口」。
**置信度**：**高**（流程与规则形态有 S25/S6/S30 一手/准一手支撑，且与行业判定尺高度吻合）。

### P5｜认证与投标的「标准符合性应答」重复劳动

**现象**

- 半年 92 张证书、国内 38 / 国际 54、覆盖多平台多机型（F17）；每张证书背后是「标准→测试大纲→报告→证书」的一次完整应答（F16）。
- 国际合格评定体系另有独立规则（F18），同一机型要出两套材料。
- 投标侧只有天工招采平台的存在证据（F29），技术偏离表、符合性声明的编制方式完全没有公开信息（G6）；画像将该场景证据强度标为「弱」。

**影响**：高价值、高频、高度模板化——同一批标准依据在不同机型、不同国家、不同招标项目里反复重组。是标准知识「被复用」最集中的地方，也是最容易靠检索+匹配+撰写压缩人力的地方。

**上游依据**：画像 §3 场景表第 3/11 行、§3.1(2)、§4.3 抓手 1、§5 第 6 项；F16、F17、F18、F29、G6。行业侧对照：案例 §六「投标应答」行（适配多智能体「高」）、§八「优先切口 1」。
**置信度**：**认证侧高、投标侧低**（认证规模与流程是 F16/F17 硬事实；投标应答是 G6 + 弱证据 S27，整体记**中**）。

---

### P6｜知识沉淀在专家与培训体系，岗位化复用不足

**现象**

- 知识载体是「人 + 课」：253 名内训师、304 门课程、三层培训体系、金风大学（F26）；标准制定侧由高管亲自出面、到标委会汇报项目储备（F12），说明关键判断集中在少数专家。
- 资产管理平台称「自主学习 27 年积累的海量业务数据，归纳出成熟管理动作」（F25），但那是数据模型与处置策略，不是标准条款（画像 §3.1(4) 判断）。
- 金风自有 AI 已有行业知识库 + 大模型做故障诊断（F30），但未披露是否覆盖标准问答（G8）。

**影响**：专家在时效率高、专家不在时断层；培训是「批量传递」但不是「任务内即时调用」。标准知识难以从「课程」变成「岗位上手就能用的判断依据」。

**上游依据**：画像 §1.4、§2.6、§3.1(4)(5)、§5 第 7/8 项；F12、F25、F26、F30、G7、G8。
**置信度**：**中低**（培训与专家集中是事实；「复用不足」缺少量化，且金风已有 AI 知识库，可能部分已解决——须访谈）。

## 三、「适合 / 不适合硬上」判定表

判定维度按任务要求：**可追溯性、判定风险、审批要求、数据可得性**。四档结论：**适合多智能体协作** / **适合但只到草稿** / **适合单点检索，不必多智能体** / **不宜硬上**。

| 痛点                 | 可追溯性要求                             | 判定风险                                   | 审批要求                       | 数据可得性                                           | 结论                                               | 建议自动化边界（AI 到哪 / 人保留什么）                                                                                                                             |
| -------------------- | ---------------------------------------- | ------------------------------------------ | ------------------------------ | ---------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **P1 版本与影响面**  | 极高：条款号、版本、生效日、适用范围     | 中：错在「漏通知」而非「错判定」           | 中：标准化归口确认             | 中：699/34/21 的元数据可得，企标与映射缺（G2、G3）   | **适合做底座，不宜单独当 POC**                     | AI 建标准台账与变更影响候选清单（按引用关系反查手册/合同/课程/机型）；**标准化归口人确认影响范围与生效通知**，AI 不自动改文档                                      |
| **P2 条款级检索**    | 高：必须带条款号+版本+适用范围           | 中低：检索错了会误导，但不直接放行         | 低：查询类无需审批             | 中低：标准文本可采买/接入，内部映射缺（G1、G3）      | **适合单点 RAG + 轻量多智能体（检索/校核双角色）** | AI 定位并引用条款、标注版本与适用机型/地区；**工程师对「引用是否适用」签字确认**；无来源不回答                                                                     |
| **P3 作业链同步**    | 高：手册/课程/巡检项要能反查到条款       | 中高：影响现场作业正确性                   | 高：专业工程师 + 培训/作业主管 | 中：手册系统与课程体系存在（F23、F26），映射缺（G7） | **适合多智能体协作（第二优先）**                   | 条款变更 Agent → 影响载体识别 Agent → 改稿 Agent → 一致性校核 Agent；产出**修订建议稿**；**专业工程师与作业主管分别签认**，发布仍走原文档流程                      |
| **P4 供应链准入**    | 高：证书编号、有效期、核验时间、条款命中 | **高：过期/范围不符不得自动准入**          | 高：采购 + 质量会签            | 高：准入流程与评价规范明确（F21、F22）               | **适合但只到「证据包 + 风险提示」**                | 证书 Agent（OCR+有效期）→ 条款比对 Agent → 风险摘要 Agent，输出证据包与红黄灯；**采购/质量会签人做准入决定**，Agent 不得写回准入结论                               |
| **P5 认证/投标应答** | 高：逐条响应、证据链接、版本             | 中高：报价、交付承诺、法律条款不可自动终稿 | 高：技术/商务/法务三签         | 中：认证侧强（F17），投标侧弱（G6、F29）             | **适合多智能体协作（第一优先）**                   | 解析 Agent → 产品/案例匹配 Agent → 合规校核 Agent → 撰写 + 交叉校对 Agent；输出**应答初稿 + 偏离表草稿**；**技术/商务/法务签批后才可提交**，报价与承诺条款由人定稿 |
| **P6 专家知识复用**  | 中：答案要带来源与版本                   | 中：答错影响判断但不放行                   | 低到中：内部问答一般无需审批   | 低：课程-标准映射、专家访谈材料均缺（G7、G8）        | **适合单点 RAG，不宜上多智能体**                   | 岗位知识助手 + 案例库检索；**不替代专家评审**；专家仍对疑难判断负责                                                                                                |

**表外两条通用判断**（来自案例 §五、§七）：

- 「编排流水线 ≠ 多智能体协作」；「多个 Agent ≠ 协作」。上表只有 P3、P5 真正需要多角色分工与交接，P1/P4 是「规则 + 证据包」，P2/P6 单点 RAG 足够。
- 「多智能体 ≠ 更可靠」。高风险处必须唯一责任人签字，Agent 的多数意见不构成授权（案例 §七 第 2 条）。

## 四、优先级排序（业务价值 × 可自动化程度 × 可验证性）

评分口径：每项 1–5 分，三项相乘取排序；「可验证性」= 上线后能否用可抽样、可复核的证据证明做对了（不含效益数字）。

| 排名  | 痛点                       | 业务价值 | 可自动化 | 可验证性 | 乘积    | 定位                                                                                       |
| ----- | -------------------------- | -------- | -------- | -------- | ------- | ------------------------------------------------------------------------------------------ |
| **1** | **P5 认证/投标符合性应答** | 5        | 4        | 5        | **100** | **首选 POC**：逐条响应天然可抽样核验，失败成本可控，人工签批点清晰                         |
| **2** | **P4 供应链准入证据包**    | 4        | 4        | 5        | **80**  | **次选 POC**：规则最明确、边界最清楚（只到证据包），但判定风险高，须先把「不自动准入」写死 |
| **3** | **P2 条款级检索**          | 4        | 5        | 3        | **60**  | **POC 的共用底座**：不单独立项，但 P5/P3 都依赖它；条款+版本+适用范围三要素必须先立住      |
| **4** | **P1 版本与影响面台账**    | 3        | 4        | 4        | **48**  | 使能型能力，随 P2 一起交付；单独做会被当成「又一个文档库」，不单独竞争 POC                 |
| **5** | **P3 作业链同步**          | 5        | 3        | 3        | **45**  | 价值最高但集成最重（手册系统、培训平台、巡检规则三处写回），排期放第二期                   |
| **6** | **P6 专家知识复用**        | 3        | 3        | 2        | **18**  | 不做 POC；用单点 RAG 试水，价值难量化                                                      |

> 注：乘积仅用于排序，不是效益预测。P3 业务价值最高（5），但可自动化与可验证性受三处系统集成拖累，故不作为首期切口。

**推荐给方案架构师的切口（与画像 §4.3 三个抓手对齐，不新增方向）**

1. **认证与投标的标准符合性应答**（画像 §4.3 抓手 1）——多智能体分工最自然，人工签批点最明确。
2. **供应链准入的条款比对**（画像 §4.3 抓手 2）——只做证据包，不碰准入结论。
3. **运维作业的标准注入**（画像 §4.3 抓手 3）——在既有 SOAM/运营知识平台上做增量，不另起炉灶；作为第三期或备选。

## 五、不宜硬上的场景（明确不做）

| 场景                                                   | 为什么不能交给 Agent                                                                         | 上游依据                                                                                        |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **认证/检测的最终签字与盖章**                          | 授权签字人不可代理；不能修改原始记录；报告要可追溯到方法、设备、校准                         | 案例 §六「检测认证/试验报告」行；画像 F16（依标 HIL 报告的出证主体是中国电科院）                |
| **供应商准入的「通过/不通过」**                        | 证书过期、认证范围不符不得自动准入；「第一条匹配」不等于已匹配；准入与经济利益、质量责任挂钩 | 案例 §六「供应链准入」行、§七 第 1 条、§八「谨慎切口」；画像 F21、F22                           |
| **设计红线的「符合/不符合」判定**                      | LLM 不能直接判定符合性；标准换版必须可追踪；结论须专业工程师签认                             | 案例 §六「设计选型/标准符合性」行；画像 F15                                                     |
| **安全类定级与作业许可（停电、动火、高空、受限空间）** | 安全措施必须人审、硬联锁、权限隔离；Agent 最多建议，不能绕过规程执行                         | 案例 §六「运维检修」行、§七 第 6 条；画像 F24（一键工单是「生成」，不是「执行」）               |
| **对外披露与 ESG/可持续报告口径**                      | 对外数字须人工核对来源与证据级别；本次协作亦不自动对外发布                                   | 案例 §九 末条；画像 §1.3 口径注意、§7 来源质量说明                                              |
| **报价、交付承诺、合同法律条款的终稿**                 | 商务与法律后果不可由 Agent 承担；必须技术/商务/法务签批                                      | 案例 §六「投标应答」行                                                                          |
| **直接写回 QMS/CMMS/ERP 等系统**                       | 无草稿态、审批、回滚、审计不可上线；受监管场景电子签名是硬要求                               | 案例 §七 第 3 条、案例 5（TrackWise 的 21 CFR Part 11 是平台合规能力，不等于 Agent 被监管批准） |
| **把培训问答包装成「业务自动化」**                     | 单点 RAG 足够，多智能体只会增加成本与不确定性                                                | 案例 §六「培训与问答」行、§八「不建议切口」                                                     |

**一句边界话术**（供方案引用）：AI 做到「找依据、做比对、出草稿、标风险」；人保留「定结论、签字、放行、对外」四类动作。

## 七、一页结论

1. **金风不缺标准，缺的是标准在任务发生时的定位与追溯**：699 项国内标准、34 项 IEC（F8），且三年增约六成（F9）；但「标准—条款—机型—市场—载体」的索引没有任何公开证据（G1、G3、G4）。这是全部痛点的事实根。
2. **三条链路的成熟度不均衡**：合规链（设计红线、认证）与契约链（供应商准则、合同）有外部审计和合同兜底；作业链（手册、课程、巡检项）是弱约束，最易失真（画像 §4.1 判断二）。
3. **第一优先是认证/投标的标准符合性应答**，第二是供应链准入的证据包，第三是运维作业的标准注入——与画像 §4.3 三个抓手一一对应，未新增方向。
4. **判定类动作一律不交给 Agent**：认证签字、准入结论、设计红线符合性、安全作业许可、对外披露、报价承诺，均为人工唯一责任（案例 §六、§七）。
5. **所有痛点均需访谈复核**；公开信息缺失只证明「未披露」，不证明「未建设」。方案对外使用前须人工核对来源与证据级别（案例 §九）。
